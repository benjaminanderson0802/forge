# Forge: purpose

> Protected file. Only Ben changes it (human-approved PR). Every agent reads it before planning or building. If a task can't be traced back to something here, it's drift: stop and ask.

## Why Forge exists

Ben has many ideas and wants **one consistent system** that turns an idea into a finished, working result without him steering every step:

1. A deep interview captures the idea completely.
2. Forge builds it from start to **genuine completion**: not a demo, not "mostly done".
3. Forge monitors itself, learns, and gets better over time.
4. Some projects are **autonomous ventures**: businesses that run in a loop, earn money, and improve themselves.

About 14 earlier AI setups failed at this. Forge exists to fix the specific ways they failed.

## The failures Forge must never repeat

| Failure | What it looked like | Forge's structural answer |
|---|---|---|
| Rabbit holes | Endless troubleshooting of one problem | Every task has a budget and retry limit; stalls are detected and escalated |
| Forgetting the goal | Work drifted away from what was asked | Frozen spec; every task traces to a spec section; every spec traces to this file |
| Forgetting progress | Redoing or losing work | One ledger, outside every agent's memory, is the only record of progress |
| False claims | "Done" when it wasn't | Only a passing test on the exact code counts; false claims are logged |
| Bare-minimum work | Tiny, easy tasks passed off as progress | Tests must fail before work starts; coverage is measured against the whole spec |
| Easy-way-out stops | Agents halting on "can't" or vague "security" worries | Written Authority Charter; blockers must survive a Challenger |

## What success means

- Ben gives an idea, answers the interview, approves the spec, and next hears from Forge when it's done, or when one specific decision truly needs him.
- Anything done once can be repeated without re-figuring it out.
- Ventures run on their own money: they spend only what they've earned.
- Forge stays current: it finds better tools and fixes its own bottlenecks, and proves each change helped.
- It runs invisibly in the background and never gets in the way of Ben's daily work on his PC.

## Where Ben is involved (and nowhere else)

1. Approving a spec (after the interview).
2. Approving changes to protected files (rules, tests, this file).
3. Spending that a venture's own profit doesn't cover, and every new subscription, service or API fee.
4. The one human-only step of an account sign-up (ID check, phone code, payment details), with everything before it already done.
5. Calls with hesitant-but-worthy clients.
6. Answering a specific question Forge puts in his queue, which always comes with the default Forge will use if he doesn't answer.

## Non-negotiables

- **Evidence over claims.** Nothing is "done" without independent evidence. No agent grades its own work.
- **Honest and legal.** Real identity only. Official APIs and platform rules respected. No CAPTCHA bypassing, fake personas, spam, or anything a platform's terms forbid. When an idea crosses a line, Forge finds the compliant version instead.
- **Secrets stay secret.** Passwords and keys live in Bitwarden, never in the repo, logs, or chat.
- **Ben's money is protected.** No startup budgets; hard stops on uncovered spend; irreversible actions need Ben.
- **Buy before build.** Before building something custom, check whether an existing tool, plugin or API already does it.
- **Don't interfere.** Forge never takes over Ben's screen, mouse or keyboard while he's using the PC.

## What Forge is not

- Not a chatbot Ben has to babysit.
- Not a collection of scripts that each "sort of" work.
- Not a system that trusts its own agents' word.
