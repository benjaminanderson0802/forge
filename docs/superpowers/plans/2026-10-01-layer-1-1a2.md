# Layer 1, sub-plan 1A (part 2): agent runtime requirements 1.3, 1.4, 1.5, 1.6 and the 1A gate (7.5)

> Implements `docs/specs/layer-1-design.md` §1 (bullets 3 to 6) and the 1A gate row of §7. Planned under
> `docs/specs/bootstrap-conductor.md` R41, R45, R62 and R63. Requirements 1.1 and 1.2 belong to another 1A sub-plan
> and are not claimed here.

## What already exists

- `core/agents.py`: `launch()` starts every agent hidden (`CREATE_NO_WINDOW | BELOW_NORMAL_PRIORITY_CLASS` on
  Windows; a new session plus `nice 10` elsewhere), kills the whole tree on timeout (`taskkill /T /F`, `killpg`) and on
  a stop flag (R49). `ClaudeAgent` runs `claude -p --output-format json --permission-mode <mode> --session-id <uuid>
  [--allowedTools a,b]` with the prompt on stdin and reads tokens from the `usage` object (R43 weighting, R46 session
  log on timeout). `CodexAgent` runs `codex exec --ignore-user-config --ephemeral --json --skip-git-repo-check -s
  <mode> -C <cwd> -o <file> [-c windows.sandbox="elevated"] [--output-schema <file>] -` and reads usage from
  `turn.completed` (fresh input + cached/10 + output + reasoning, R43).
- `core/bootstrap.py`: `Conductor._call` (stop check, cap check, readiness launch gate, prompt blocks) and
  `_guarded_run` (run record, tamper fingerprint, metering, holds) are the only launch path.
- Nothing implements design 1.6 (the free local fallback): no `--oss` / `--local-provider ollama` command exists.
- Nothing checks the readiness map against independent observation (gate 7.5).

So 1.3, 1.4 and 1.5 get evidence tasks (R63) that prove them through the real conductor path (`Conductor._call`
with real `ClaudeAgent` / `CodexAgent` objects whose command is a fake executable script), 1.6 gets an ordinary
task, and the gate gets an ordinary task that builds a read-only readiness audit and runs the adapter tests.

## L1A2_1: Hidden, low-priority, time-limited launches and the Claude adapter, through the conductor

Covers 1.3 and 1.5. Evidence task (R63). Files in scope: `core/agents.py`. Test file:
`tests/core/test_l1a_claude_runtime.py`.

The code exists: `core.agents.launch`, `_kill_tree`, `ClaudeAgent`, `parse_claude`, `claude_log_tokens`, and the
conductor path `Conductor._call` / `_guarded_run` in `core/bootstrap.py`. Change nothing unless a test or judge fails.
The tests must pass on today's code and fail on an empty `core/agents.py`.

Fixture: the shared conductor fixture with `builder = ClaudeAgent(cmd=[sys.executable, fake_claude],
permission_mode='acceptEdits', allowed_tools=['Read', 'Edit'], projects_dir=<tmp>/projects)`,
`drift_keeper = ClaudeAgent(cmd=..., permission_mode='plan', allowed_tools=['Read', 'Glob', 'Grep'])`,
`planner = ClaudeAgent(cmd=..., permission_mode='acceptEdits')` (no tools) and `reviewer = CodexAgent(cmd=[sys.executable,
fake_codex], sandbox='read-only')`; other roles are FakeAgents.

Fake claude (mode from `FORGE_FAKE_MODE`) logs `{argv, cwd, stdin, pid, priority}`, where priority is
`ctypes.windll.kernel32.GetPriorityClass(GetCurrentProcess())` on Windows and `os.nice(0)` elsewhere. Mode `ok` prints
one line `{"type": "result", "is_error": false, "result": "{\"status\": \"done\"}", "usage": {"input_tokens": 100,
"output_tokens": 20, "cache_creation_input_tokens": 5, "cache_read_input_tokens": 1005}}`. Mode `error`: the same
with `is_error` true and result `boom`. Mode `hang`: writes `<FORGE_FAKE_PROJECTS>/p/<session-id>.jsonl` with one
record `{"message": {"id": "m1", "usage": {"input_tokens": 40, "output_tokens": 2}}}`, starts a grandchild Python
process that sleeps 120 s, logs its pid, then sleeps 120 s. Fake codex logs the same fields; mode `ok` writes
`{"verdict": "pass", "reasons": []}` to the file after `-o` and prints
`{"type": "turn.completed", "usage": {"input_tokens": 10, "output_tokens": 1}}`; mode `hang` as for claude.
A process counts as gone when, on Windows, `OpenProcess(0x00100000 | 0x1000, False, pid)` fails or
`WaitForSingleObject(h, 0) == 0`; elsewhere when `os.kill(pid, 0)` raises or `/proc/<pid>/stat` shows state `Z`.

Acceptance criteria:
1. Hidden, low priority (1.3), for Claude and Codex. With `subprocess.Popen` wrapped by
   `unittest.mock.patch('subprocess.Popen', side_effect=<recorder calling the real Popen>)`,
   `c._call('builder', 'do X', S_BUILD, cwd=wt)` and `c._call('reviewer', 'check', S_REVIEW, cwd=wt)` each launch
   their fake exactly once. On Windows the recorded `creationflags` include both `subprocess.CREATE_NO_WINDOW` and
   `subprocess.BELOW_NORMAL_PRIORITY_CLASS`; elsewhere `start_new_session` is True. The child's own logged priority
   is `0x4000` (below normal) on Windows, or at least 10 above the test process's `os.nice(0)` elsewhere.
2. Hard timeout kills the whole tree (1.3). Builder `ClaudeAgent(timeout_s=3)` in `hang` mode: `c._call` returns
   within 30 s a result with `ok` False and an error containing `timed out after 3s`; the logged grandchild is gone
   within 10 s; the run's `state/runs/<id>-builder-*/output.json` has `ok: false`. The same for the reviewer
   `CodexAgent(timeout_s=3)` in `hang` mode.
3. A caller deadline only shortens: `c._call('builder', ..., timeout_s=2)` with an agent timeout of 1800 times out
   with `timed out after 2s`.
4. A stop kills the tree: builder in `hang` mode with a 60 s timeout; a timer thread writes `state/KILL` 1 s after
   the call starts; `c._call` raises `core.bootstrap.Stopped` within 10 s and the grandchild is gone within 10 s.
5. Claude command (1.5). The builder's argv after the script path is exactly `['-p', '--output-format', 'json',
   '--permission-mode', 'acceptEdits', '--session-id', <uuid4>, '--allowedTools', 'Read,Edit']`; the drift keeper's
   has `--permission-mode plan` and `--allowedTools Read,Glob,Grep`; the planner's has no `--allowedTools`. The
   prompt arrives on stdin (print mode reading the prompt from stdin is the form of `-p <prompt>` Forge uses; it
   avoids Windows command-line limits): stdin starts with the prompt given to `_call`, contains the capability-map
   block, and ends with the schema line naming `status`. The logged cwd is `wt`. The session id is a valid UUID4
   and differs between two calls.
6. Usage from the `usage` object (1.5). `ok` mode: `ok` True, `data == {'status': 'done'}`, tokens
   100 + 20 + 5 + 1005 // 10 = 225; `output.json` records tokens 225 and provider `claude`;
   `c.meter.used_today('claude') == 225`. `error` mode: not ok, error `boom`, and its 225 tokens are still metered.
   `hang` mode: the timed-out run is metered from the session log (R46): 42 tokens recorded and metered.
7. Caps hold before launch: after one `ok` run, set `c.limits['claude_daily_token_cap'] = 225`; the next
   `c._call('builder', ...)` raises `core.bootstrap.Capped` and the fake logs no new launch.

## L1A2_2: Codex runs isolated and is metered from turn.completed, through the conductor

Covers 1.4. Evidence task (R63). Files in scope: `core/agents.py`. Test file: `tests/core/test_l1a_codex_runtime.py`.

The code exists: `core.agents.CodexAgent`, `parse_codex`, `strict_schema`, `_codex_error`, and the conductor path
`Conductor._call` / `_guarded_run`. Change nothing unless a test or judge fails. The tests must pass on today's code
and fail on an empty `core/agents.py`.

Fixture: the shared conductor fixture with `reviewer = CodexAgent(cmd=[sys.executable, fake_codex],
sandbox='read-only')` and `test_writer = CodexAgent(cmd=..., sandbox='workspace-write')`; other roles are FakeAgents.
The fake codex reads the values after `-o`, `--output-schema`, `-s` and `-C` and logs `{argv, cwd, stdin, schema}`,
where `schema` is the parsed content of the `--output-schema` file (read before it exits) or null. Modes (from
`FORGE_FAKE_MODE`): `ok` prints JSON lines `{"type": "thread.started"}` and `{"type": "turn.completed", "usage":
{"input_tokens": 1000, "cached_input_tokens": 400, "output_tokens": 50, "reasoning_output_tokens": 30}}` and writes
the message from `FORGE_FAKE_MESSAGE` (default `{"verdict": "pass", "reasons": ["fine"]}`) to the `-o` file;
`nocache`: the same usage without `cached_input_tokens`; `overcache`: input 100, cached 500, output 0, reasoning 0;
`failed`: prints `{"type": "turn.failed", "error": {"message": "model refused"}}` and exits 1; `noturn`: writes the
`-o` file, prints no `turn.completed`, exits 0.

Acceptance criteria:
1. Isolated command. `c._call('reviewer', 'review this', S_REVIEW, cwd=wt)`: the argv after the script path is
   exactly `['exec', '--ignore-user-config', '--ephemeral', '--json', '--skip-git-repo-check', '-s', 'read-only',
   '-C', str(wt), '-o', <file>]`, then on Windows `['-c', 'windows.sandbox="elevated"']` (R16) and elsewhere nothing,
   then `['--output-schema', <file>, '-']`. The `-o` and schema files are outside `wt` and the repo and no longer
   exist after `_call` returns. stdin starts with `review this`. The logged schema equals
   `core.agents.strict_schema(S_REVIEW)` (every object has `additionalProperties: false` and requires all its
   properties).
2. Sandbox follows the role. `c._call('test_writer', 'write tests', None, cwd=wt)`: `-s workspace-write`, `-C wt`,
   no `--output-schema`, last argument `-`, and the Windows override present for this mode too.
3. Usage from `turn.completed`, cached input counted separately. `ok`: `ok` True, `data == {'verdict': 'pass',
   'reasons': ['fine']}`, tokens (1000 - 400) + 400 // 10 + 50 + 30 = 720; `output.json` records tokens 720 and
   provider `codex`; `c.meter.used_today('codex') == 720`. `nocache`: 1080. `overcache`: cached is clamped to the
   input, so 0 + 10 = 10.
4. `failed`: not ok, the error contains `exit 1` and `model refused`, tokens 0, the meter unchanged,
   `output.json` has `ok: false`.
5. `noturn`: not ok even though the `-o` file has text.
6. Shape: with `FORGE_FAKE_MESSAGE` `{"reasons": []}` and schema `S_REVIEW`, not ok with error
   `output did not match the required shape`.
7. Readiness gates the launch: with `probes={'codex': FakeAgent(lambda p, c: ('nope', 0), provider='codex'), ...}`,
   `c._call('reviewer', ...)` raises `core.bootstrap.NotReady` and the fake logs no launch.

## L1A2_3: Free local fallback for chores, never for a role

Covers 1.6. Ordinary task. Files in scope: `core/agents.py`, `core/bootstrap.py`. Test file:
`tests/core/test_l1a_free_fallback.py`.

Design 1.6: a free fallback, `codex exec --oss --local-provider ollama`, for chores such as summarizing logs, never
for independent roles. Build:

- `core/agents.py`: `FREE_PROVIDER = 'ollama'` and `class FreeAgent` with `provider = 'ollama'`, `should_stop = None`,
  `__init__(self, timeout_s: int = 600, model: str | None = None, cmd: list[str] | None = None)` (default cmd
  `['codex']`) and `run(self, prompt, cwd, schema=None, timeout_s=None) -> AgentResult` (never raises). Argv:
  resolved cmd + `['exec', '--oss', '--local-provider', 'ollama', '--ignore-user-config', '--ephemeral', '--json',
  '--skip-git-repo-check', '-s', 'read-only', '-C', str(cwd), '-o', <file in a fresh temp folder>]`, then
  `['-m', model]` when a model is set, then on Windows `['-c', 'windows.sandbox="elevated"']` (R16), then
  `['--output-schema', <strict schema file>]` when a schema is given, then `['-']`. The sandbox is always
  `read-only`. The prompt goes on stdin through `launch()` (hidden, below-normal priority, tree kill, `should_stop`)
  with the deadline rule of `_deadline`. The result is parsed like Codex (`parse_codex`) but reports provider
  `ollama`; a missing command gives a failed result `agent command not found: ...`; a timeout gives a failed result.
  The temp folder is removed afterwards. `ClaudeAgent` and `CodexAgent` behaviour must not change.
- `core/bootstrap.py`:
  - `Team.__post_init__` raises `ValueError` naming the field when any of the six members has
    `getattr(member, 'provider', None) == agents.FREE_PROVIDER` (the fallback can never fill a role, D-020).
  - `Conductor.__init__` gains keyword `chore_agent=None`; None means `FreeAgent(limits.get('chore_timeout_s', 600))`
    (constructing it launches nothing). A `manager` whose provider is `ollama` raises `ValueError`.
  - `Conductor.chore(self, label: str, prompt: str, cwd: Path, schema: dict | None = None, timeout_s: float | None =
    None) -> AgentResult`: `label` must match `^[a-z0-9_]{1,30}$` (else `ValueError`). In order: `_raise_if_stopped()`;
    `Capped('ollama')` when `self.meter.over('ollama', self.limits)` (runs per day and holds apply);
    `self._launch_gate('ollama')` (needs `git` and `ollama` evidence, else `NotReady`); then
    `self._guarded_run('chore-' + label, self.chore_agent, prompt, cwd, schema, timeout_s=timeout_s)`, so the run
    gets a run record, the tamper check, metering under provider `ollama` and stop handling. No capability-map or
    dead-end blocks are appended.
  - `Conductor.summarize_log(self, text: str, cwd: Path) -> str | None`: runs `chore('summarize_log', ...)` with a
    prompt asking for a summary of at most 10 lines followed by the last 20000 characters of `text`; returns the
    stripped text of an ok result, else None. `NotReady` and `Capped` also give None; `Stopped` and `Tampered`
    propagate.

Acceptance criteria (fake codex executable as `cmd=[sys.executable, fake]`, logging argv, cwd and stdin; it prints
`{"type": "turn.completed", "usage": {"input_tokens": 300, "cached_input_tokens": 100, "output_tokens": 20}}` and
writes `log summary` to the `-o` file; the shared conductor fixture with
`checks={'git': ..., 'ollama': lambda: (True, 'HTTP 200')}`):
1. `c.summarize_log('line\n' * 10, wt)` with `chore_agent=FreeAgent(cmd=[sys.executable, fake])` returns
   `log summary`. The argv after the script is exactly the list above with `wt` (no `-m`), including `--oss`,
   `--local-provider ollama` and `-s read-only`, the Windows override on Windows only, and `-` last; stdin contains
   the log text.
2. The run goes through the guarded path: a `state/runs/<id>-chore-summarize_log-*/output.json` exists with
   provider `ollama` and tokens 200 + 10 + 20 = 230, and `c.meter.used_today('ollama') == 230`.
3. The launch is hidden and below normal priority: with `subprocess.Popen` wrapped as a recorder, on Windows the
   fake's `creationflags` include `CREATE_NO_WINDOW` and `BELOW_NORMAL_PRIORITY_CLASS`; elsewhere `start_new_session`.
4. `FreeAgent(model='llama3.2', cmd=...)` adds `-m llama3.2`; with a schema, `--output-schema` points to a file
   holding `strict_schema(schema)`.
5. With `checks` making `ollama` fail, `c.chore('x', 'p', wt)` raises `NotReady` and `summarize_log` returns None;
   neither launches the fake.
6. With `limits['agent_runs_per_day'] = 0`, `chore` raises `Capped` without launching; with `state/KILL` present it
   raises `Stopped` without launching.
7. `Team(...)` with any one of the six members a `FreeAgent` (or any agent with provider `ollama`) raises
   `ValueError` naming that member; a `Conductor` given `manager=FreeAgent()` raises `ValueError`; a bad label
   (`'Bad Label'`) raises `ValueError`.
8. Without the `ollama` executable: `FreeAgent(cmd=['no-such-forge-cmd']).run('p', wt)` returns not ok with
   `agent command not found`. A fake that sleeps with `FreeAgent(timeout_s=2)` returns not ok with
   `timed out after 2s`.

## L1A2_4: 1A gate: adapter tests plus a truthful readiness audit on the PC

Covers 7.5. Ordinary task. Depends on L1A2_1, L1A2_2, L1A2_3. Files in scope: `core/readiness_audit.py` (new).
Test file: `tests/core/test_l1a_gate.py`. Needs: github, gmail, docker, n8n, ollama, browser, python_libs.

Gate 7.5 is: adapter tests pass, and the readiness check shows every capability truthfully on the PC. Build
`core/readiness_audit.py` (standard library plus what `core` already uses). It **never writes under Forge's live
`state/`** (reading only), and it **launches no AI**: Claude and Codex evidence is verified from the conductor's own
recorded, metered probe runs, so D-020's caps and the R60 admission stay the only launch path.

- `PLAIN = tuple(core.readiness.PLAIN_CHECKS)` (git, github, gmail, docker, n8n, ollama, python_libs, browser).
- `OBSERVERS: dict[str, Callable[[float], tuple[bool, str]]]`, one per plain capability, each taking a timeout in
  seconds and using a different mechanism from `core.readiness`: git: `git hash-object --stdin` of `forge\n` equals
  `hashlib.sha1(b'blob 6\x00forge\n')`; github: `gh api user --jq .login` exits 0 with a non-empty login; docker:
  `docker version --format {{.Server.Version}}` exits 0 with a non-empty version; n8n: `http.client` GET
  `127.0.0.1:5678/healthz` with a 2xx status; ollama: `http.client` GET `127.0.0.1:11434/api/version` returning JSON
  with `version`; python_libs: a separate `sys.executable` process reporting `importlib.util.find_spec` for
  requests, yaml, httpx, pandas, pdfplumber, keyring, playwright; gmail: the `forge-gmail` keyring password for
  `core.readiness.GMAIL` and an `imaplib.IMAP4_SSL('imap.gmail.com', 993)` login and logout (no mailbox read, nothing
  sent; the password never appears in any detail); browser: a separate `sys.executable` process that launches
  headless Chromium with Playwright, sets content `<p>forge</p>` and reads back `forge`. Every subprocess is hidden
  (`CREATE_NO_WINDOW` on Windows), has stdin closed and a timeout; any exception is `(False, '<Type>: <msg>')`.
- `observe(observers, timeout_s) -> dict[str, dict]`: runs them concurrently in daemon threads against one deadline;
  `{name: {'ok': bool, 'detail': str}}`; one not reported by the deadline is `ok False`, `observer timed out`.
- `check_now(work: Path, limits: dict, checks=None) -> dict`: builds a `core.bootstrap.Conductor` with `state=work /
  'state'`, `work=work / 'work'`, `repo=work`, `checks=checks or core.readiness.PLAIN_CHECKS`, `probes={}`, no-op mailer,
  empty inbox, `gh` returning `(0, '')`, `push=False`; calls `_refresh_readiness(force=set(checks))` and returns
  `core.readiness.read_map(work / 'state' / 'capabilities.json')` (the persisted map, as the conductor wrote it).
- `live_state_dirs(root: Path) -> list[Path]`: `root/state/bootstrap` and every `root/state/lanes/<lane>` that holds
  a `capabilities.json`, sorted.
- `trace_probe(state_dir: Path, name: str, entry) -> tuple[bool, str]` for `claude` and `codex`: the entry must be a
  dict with bool `ok`, str `detail` and a timezone-aware `checked_at`. The matching run is the earliest folder
  `state_dir/runs/<YYYYMMDDTHHMMSS>-probe-<name>-<hex>` whose UTC timestamp is at or after `checked_at` truncated to
  the second and at most 3600 s after it. It must have `prompt.md` equal to `core.readiness.PROBE_PROMPT` and an
  `output.json` whose `provider` equals `name`; `core.readiness.probe_ok` of the recorded result (an object with the
  recorded `ok`, `text`, `error`, `tokens`) must equal the entry's `ok` and its detail (truncated to `DETAIL_MAX`)
  must equal the entry's `detail`. Otherwise `(False, <reason>)`, for example `no probe run`, `prompt differs`,
  `provider differs`, `ok differs`, `detail differs`.
- `audit(root: Path, work: Path, *, limits=None, checks=None, observers=None, timeout_s=None, clock=None) -> dict`:
  limits default `core.agents.load_limits(core.readiness.FORGE_ROOT)`, `timeout_s` default
  `check_timeout_s - 15` (at least 5). It runs `check_now` and `observe`, then for each plain name: truthful when the
  persisted entry exists, is well formed (bool `ok`, str `detail`, timezone-aware `checked_at` within 600 s of the
  audit start) and its `ok` equals the observed `ok` (a failure both see is truthful; a disagreement or an observer
  timeout is not). For every live state dir it checks that all ten names of `core.readiness.CHECKS` are present and
  traces `claude` and `codex`. Report: `{'checked_at', 'state_dirs', 'plain': {name: {'map', 'observed', 'truthful',
  'why'}}, 'ai': {<state dir relative to root>: {name: {'map', 'run', 'truthful', 'why'}}}, 'missing': {...},
  'truthful': bool}`; `truthful` is True only when there is at least one live state dir, nothing is missing and every
  entry is truthful. The report is written atomically to `work/readiness_audit.json` and returned.
- `main(argv=None) -> int`: `python -m core.readiness_audit [--root PATH] [--out DIR]`; root default env
  `FORGE_LIVE_ROOT` else `Path.home() / 'Forge'`, out default a new temp folder; prints one line per capability
  (`OK`/`FAIL`, truthful or not, the detail) and returns 0 when truthful, else 1.

Acceptance criteria:
1. Adapter tests: a subprocess `[sys.executable, '-m', 'unittest', 'tests.core.test_agents',
   'tests.core.test_l1a_claude_runtime', 'tests.core.test_l1a_codex_runtime', 'tests.core.test_l1a_free_fallback']`
   run from the repo root (timeout 900 s) exits 0 and reports `OK`.
2. Plain logic with fakes: fake checks and observers that agree (including both failing) give `truthful` True; a
   check saying ok while its observer says not ok gives that capability and the report `truthful` False with a reason;
   an observer that sleeps 30 s with `timeout_s=1` makes `audit` return within 10 s with `observer timed out` and
   `truthful` False.
3. `check_now` calls each fake check exactly once, launches no agent (the conductor has `probes={}`) and the returned
   map is what is on disk under `work/state/capabilities.json` with every name and a timezone-aware `checked_at`.
4. `trace_probe` with a fake state dir: a matching recorded run (`ok` true, text `ok`, tokens 5, entry detail
   `ok (5 tokens)`) is truthful; a recorded failure whose error equals the failing entry's detail is truthful;
   each of these is not: no run at or after `checked_at` (only an earlier one), wrong prompt, wrong provider, entry ok
   with a failed recorded run, a token count that differs.
5. `audit` on a fake live root never changes it: a sha256 of every file under the fake `root/state` is equal before
   and after; a live state dir missing any of the ten names makes the report `truthful` False under `missing`.
6. Truthful on the PC (the live gate check): when `FORGE_LIVE_ROOT` (else `Path.home() / 'Forge'`) has
   `state/bootstrap/capabilities.json`, `audit(root, tmp, checks=core.readiness.PLAIN_CHECKS,
   observers=OBSERVERS)` with the real limits finishes within `4 * check_timeout_s` seconds, writes
   `tmp/readiness_audit.json` equal to the returned report, covers all eight plain names and every live state dir,
   and has `truthful` True; on failure the test message lists every untruthful entry with its reason. When that live
   root does not exist (CI, Linux) this one test is skipped with that reason; all other tests run everywhere.

## Self-check against the rules (R45)

- R1: every `test_cmd` is `python -m unittest <its own test file>`, and every test file is one of the task's
  `test_files`.
