## Task L1E_1: Evidence: the queue file and the instant / digest / quiet-hours routing (6.1, 6.2)

- evidence: true
- files_in_scope: `core/channel.py`, `core/bootstrap.py`
- test_files: `tests/core/test_l1e_queue_routing.py`
- test_cmd: `python -m unittest tests/core/test_l1e_queue_routing.py`
- covers: 6.1, 6.2

This is an evidence task (R63): the code already exists and the builder changes nothing. The tests must pass on the
current code and must fail on an empty `core/channel.py`. Design §6: "Queue: ledger/queue.jsonl. Each item has an id,
kind, question, default, deadline and status. Instant email only for the D-023 kinds. The digest goes out at 08:00
local. Quiet hours are 23:00-07:00, except emergencies." The conductor's state folder (`conductor.state`) is its ledger
folder, so the queue file is `conductor.state / "queue.jsonl"`. The policy is on when `limits` has `digest_hour`
(E4); the tests run with `{"digest_hour": 8, "quiet_start": 23, "quiet_end": 7, "mail_per_hour": 20,
"mail_per_day": 50}` (so the mail budget never hides the routing) and a fixed local zone
(`timezone(timedelta(hours=-5))` set as `conductor.local_tz`, with `conductor.clock` returning a fixed aware datetime).

Tests must prove, against the real conductor (`_channel_conductor`):

1. **Queue file (6.1).** After `c._ask("blocked", "Task T1 is blocked", "details", task="T1", deadline="2026-10-02T08:00:00+00:00")`
   and `c._ask("replan", "Forge paused", "reasons")`, `state/queue.jsonl` exists, has one JSON object per line, one
   per open question, each with keys `id, kind, question, default, deadline, status` (plus `via, code, delivered,
   halt`); `status == "open"`; `question` is the subject; `default` is `channel.default_for(kind)`; the blocked item's
   `deadline` is the one given and the replan item's is `None`. When a question is answered (owner reply with its
   `[Forge Q-<id> <code>]` subject through `inbox` + `c._handle_inbox()`), its line disappears and the other stays.
   `channel.write_queue` writes atomically (no `.tmp` left behind) and skips non-dict or non-open entries.
2. **Instant kinds (6.2).** `channel.INSTANT_KINDS == {"gate", "replan", "capability", "spend", "customer", "tamper"}`.
   At 12:00 local, asking each instant kind sends one email at once whose subject starts `[Forge Q-<qid> <code>]` and
   whose body ends with `If you don't answer: <default>`; asking `blocked` or `merge` sends nothing, and the question
   is stored with `hold` and `digest` true and `via == "digest"` in `queue.jsonl`. Without `digest_hour` in limits, a
   `blocked` question is mailed at once (policy off = old behaviour).
3. **Digest at 08:00 local.** With one held `blocked` question: `c._channel_tick()` at 07:59 local sends nothing; at
   08:00 local it sends exactly one email whose subject starts `[Forge] Daily digest` and whose body lists the
   question, its default and its `[Forge Q-<id> <code>]` answer line; a second tick at 08:30 and at 20:00 the same day
   sends nothing; at 08:00 the next local day it sends one again. `channel.build_digest` subject never contains
   `[Forge Q-`.
4. **Quiet hours except emergencies.** `channel.is_quiet` is True at 23:00, 02:00 and 06:59 and False at 07:00 and
   22:59 local. At 23:30 local an instant `gate` question sends nothing and stays `delivered: False`; no digest is
   sent by `_channel_tick`; `_send` returns False without counting it in `mail_log.json`; but a halt alert
   (`c._ask("tamper", "Forge stopped", "x", halt=True)`) is sent at once. At 07:00 local, `c._handle_inbox()`
   delivers the held gate question (one email, `delivered` becomes True).

Do not edit any existing test, drill or module.

## Task L1E_2: Replies: "n" is a real answer to a gate or a blocked merge (6.3)

- files_in_scope: `core/bootstrap.py`
- test_files: `tests/core/test_l1e_replies.py`
- test_cmd: `python -m unittest tests/core/test_l1e_replies.py`
- covers: 6.3

Design §6: "Replies are read from Gmail over IMAP, matched by `[Forge Q-<id>]` in the subject, and accepted only
from Ben's address. Answers: y, n, STOP or free text." Reading, matching, the owner check and STOP already work
(`gmail_inbox`, `Conductor._handle_inbox`, `_from_owner`, `is_stop`). The gap is `n`: in `Conductor._answer`, a
`gate` question answered `n` returns without recording anything, and a `merge` question answered `n` calls
`Journal(self.state).unblock(...)`, which retries the blocked merge as if Ben had approved it. Build the missing part.

Change only `Conductor._answer` in `core/bootstrap.py`. Compute `first = reply.split()[0].lower().strip(".!,") if
reply.split() else ""` (as the gate branch already does). For `q["kind"]` in `("gate", "merge")` and `first in {"n",
"no"}`: append `body.strip()[:NOTE_CAP]` to `q["replies"]` (a list, kept to the last `NOTES_KEEP` entries, created if
missing), set `q["declined_at"] = self.clock().isoformat()`, log `f"Q-{qid} declined by the owner: nothing merged"`
with `self._log`, write `questions.json` (via `self._write("questions.json", _prune_questions(qs))`) and return. The
question stays `open` (so the layer keeps waiting, as its default says, and a later `y` can still approve), no `gh`
call is made, and for `merge` the journal record is not unblocked. Everything else in `_answer` is unchanged: a gate
`y`/`yes` still labels and merges, any other gate reply is still ignored, any other merge reply still unblocks, and
free text still answers `blocked`, `replan` and `capability` questions as today.

Acceptance criteria (tests use `_channel_conductor` from `drills.run_drills` with `c.gh` replaced by a recorder
returning `(0, "")`, and the real `core.bootstrap.gmail_inbox(owner, state, imap_factory=..., clock=...)` driven by a
fake IMAP object: `login`, `select`, `search(None, crit) -> ("OK", [b"1 2 ..."])`, `fetch(n, spec) -> ("OK",
[(b"n (...)", raw_bytes), b")"])`, `logout`, recording every call):
1. **IMAP.** The reader logs in as the owner, selects `INBOX`, searches with criteria containing `SUBJECT "[Forge"` and
   `SUBJECT "STOP"`, and only ever fetches with `BODY.PEEK[...]` (never `store`, never a plain `BODY[]`). The first
   read returns nothing and only records what is there (`inbox_seen.json`); a later read returns a new message as
   `{"from", "subject", "body", "message_id", "outgoing": False}` with the decoded subject and the text/plain body,
   skips a message with `X-Forge-Outgoing: 1`, and never returns the same Message-ID twice.
2. **Matching.** Feeding that reader's output to the conductor (`c.inbox = reader`): an owner reply whose subject
   holds `[Forge Q-<id> <code>]` of an open `blocked` question answers that question only (status `answered`,
   `answer` = the free text); the same subject with another question's code, or a non-open question, answers nothing.
3. **Owner only.** The same reply from `mallory@evil.example`, from `"ben@example.com" <mallory@evil.example>` or from
   two addresses changes nothing; an owner `STOP` creates `state/KILL` and the next `step()` returns `"killed"`.
4. **y.** A gate (`c._ask("gate", "layer-1 is ready", "report", pr="7")`) answered `y` from the owner calls `gh` with
   `["pr", "edit", "7", "--add-label", "human-approved"]` then `["pr", "merge", "7", "--merge", "--delete-branch"]`
   and becomes `answered`.
5. **n.** A gate answered `n` (and one answered `No.`) stays `open`, has the reply in `replies` and a `declined_at`,
   and `gh` is never called; a later `y` still approves it as in 4. A `merge` question answered `n` stays open and the
   merge journal is not unblocked (spy on `core.bootstrap.Journal.unblock` with `unittest.mock.patch.object` and
   assert it was not called); answered `retry now`, `unblock` is called once and the question is `answered`.

All existing tests and drills must still pass.

## Task L1E_3: The status page's Approve works for every question (6.4)

- files_in_scope: `core/status_page.py`
- test_files: `tests/core/test_l1e_status_page.py`
- test_cmd: `python -m unittest tests/core/test_l1e_status_page.py`
- covers: 6.4

Design §6: "Status page at http://127.0.0.1:8765. It is bound to localhost only and shows the queue, current work,
caps and capabilities, with Approve / Stop buttons." Binding, host and origin checks, Stop, the queue, current work,
caps and capabilities already exist (E5). The gap is Approve: `render` shows an Approve button only for `gate`
questions, and the conductor refuses every answer for a kind in `channel.EMAIL_ONLY_KINDS` (`gate`, `merge`,
`spend`) that comes from the drop folder (Live-run P1: anything on the PC can write there), so the page's Approve
never approves anything, and no other kind has an Approve at all. Build the honest version, in `core/status_page.py`
only. The server's POST handling stays exactly as it is.

- `render(state, limits, now=None, *, local_tz=None, shared=None, forge_root=None, nonce=None, owner=None)`: new
  keyword `owner: str | None`. For each open question in the queue:
  - kind **not** in `channel.EMAIL_ONLY_KINDS`: the answer form gets `<button type=submit name=approve
    value=y>Approve</button>` (posting `approve=y`, which the server already turns into the answer `y`).
  - kind in `channel.EMAIL_ONLY_KINDS`: no Approve submit button. Instead an `<a class=approve-mail href="...">Approve
    by email</a>` link whose href is `"mailto:" + (owner or "") + "?subject=" + quote(channel.answer_tag(qid, code) +
    " y", safe="") + "&body=y"` (HTML-escaped), and the line `This approval counts only by email from you.`
  - the free-text Answer form stays for every question (so the page still has one `action="/answer"` form per open
    question).
- `make_server(..., owner: str | None = None)` passes `owner` to `render` for `GET /`. `main(argv)` adds
  `--owner` (default `"benjaminanderson0802@gmail.com"`, the same default as `core.bootstrap`'s `--owner`) and passes
  it to `make_server`.

Acceptance criteria (tests build a state folder like `tests/core/test_status_page.py`'s `PageHarness`, with an open
`gate` (code `gatecode`, pr 7), an open `blocked` and an open `replan` question, a `queue.json` with a `tests_ok`
task, `mail_log.json`, `meter.json` and `capabilities.json`):
1. `render(..., owner="ben@example.com")` shows each open question with its default, the current task, the email and
   token caps, each capability with OK/BROKEN, and a Stop form posting to `/stop`; the `blocked` and `replan` cards each
   have an `approve` submit button; the `gate` card has no submit button named `approve` but has the `Approve by email`
   link. Unquoting that link's subject gives a text the conductor's own pattern `\[Forge Q-([\w-]+) ([\w-]{8})\]`
   matches with the gate's id and code.
2. **End to end, email approve.** On a real conductor (`_channel_conductor`, recording `c.gh`), a gate asked with
   `pr="7"`: rendering its state with the owner and sending the owner email the link describes (from
   `ben@example.com`, that subject, body `y`) through `inbox` + `c._handle_inbox()` labels and merges PR 7 and closes
   the question.
3. **End to end, page approve.** On the same kind of conductor, write `(c.state / "PAUSED").write_text("x")` and ask
   `c._ask("replan", "Forge paused", "reasons")`. A real server from `make_server(c.state, c.channel_in.parent,
   c.limits, port=0, outbox=status_page.AnswerOutbox(c.channel_in, <tmp dir>, idle=lambda *_: True), owner=...)`
   accepting `POST /answer` with `qid`, `code`, `approve=y` and a same-origin `Origin` returns 303; after
   `outbox.flush()` and `c._handle_inbox()`, the replan question is `answered` with `y` and `PAUSED` is gone.
4. **Localhost only.** `make_server(..., host="0.0.0.0")` raises ValueError; the server's address is `127.0.0.1`;
   `PORT == 8765`; a GET with `Host: evil.example` is refused (403) and a GET with `Host: 127.0.0.1:<port>` returns
   200 with the page; `POST /stop` from the page's origin creates `state/KILL` and the conductor's next `step()`
   returns `"killed"`.

## Task L1E_4: 1E gate: STOP by email halts, a reply answers the right question, a foreign sender is ignored (7.9)

This is an evidence task (R63) and the 1E gate. It runs after L1E_2 and L1E_3 are merged; the builder changes
nothing. The tests must pass on the current code and fail on an empty `core/channel.py`. Design §7 gate for 1E:
"Queue, instant email, digest, reply reading, status page | Drills: STOP by email halts; a reply answers the right
question; a foreign sender is ignored". These drills exist in `drills/run_drills.py`: `DRILLS` lists
`(17, "1E: STOP by email halts", drill_17)`, `(18, "1E: A reply answers the right question", drill_18)`,
`(19, "1E: A foreign sender is ignored", drill_19)`, plus `(20, "1E: The status page Stop button halts", drill_20)`
and `(21, "1E: The digest policy cannot flood", drill_21)`.

Tests must check:
1. **Gate drills.** Import `drills.run_drills` (run from the repo root, as `test_cmd` does) and assert `DRILLS` holds
   entries 17 to 21 with exactly those names and functions, and that calling each of `drill_17()` to `drill_21()`
   returns a non-empty string without raising.
2. **STOP by email halts (real conductor, `_channel_conductor`).** With an open gate question and a queue holding a
   `todo` task, an owner email `STOP` (subject `Re: [Forge] x`, body `STOP`) makes `step()` return `"killed"`,

4. **A foreign sender is ignored.** For senders `mallory@evil.example`, `"ben@example.com" <mallory@evil.example>`
   and `mallory@evil.example, ben@example.com`: a `STOP` and a correct-code `y` to an open gate set no `KILL`, answer
   nothing and call no `gh`.
