## Task L1C_1: Evidence: the Manager is Claude, read-only, and its answer is fully schema-checked (2.1)

- evidence: true
- files_in_scope: `core/manager.py`
- test_files: `tests/core/test_l1c_manager_evidence.py`
- test_cmd: `python -m unittest tests/core/test_l1c_manager_evidence.py`
- covers: 2.1

This is an evidence task (R63): the code already exists and the builder changes nothing. The tests must pass on the
current code and must fail on an empty `core/manager.py`. Design §2: the Manager is "Claude, read-only | may write
nothing | plan.schema.json". In Forge the plan schema is `core.manager.S_MANAGER` (an inline JSON Schema: object with a
required `tasks` array; each task requires `id, title, section, covers, files_in_scope, test_files, test_cmd`,
optional `needs`), checked completely by `core.manager.validate_proposal(data, requirements, existing_ids) -> (clean,
problems)`.

Tests must prove, against the real code:

1. **Claude, read-only.** `core.bootstrap.real_manager({"agent_timeout_s": 60})` returns a `core.agents.ClaudeAgent`
   with `provider == "claude"`, `permission_mode == "plan"` and `allowed_tools == ["Read", "Glob", "Grep"]` (no Edit,
   Write or Bash).
2. **Schema.** `S_MANAGER["required"] == ["tasks"]` and the task item's `required` equals `list(manager.REQUIRED)`.
   `validate_proposal` with a well-formed one-task proposal returns one clean task (normalised paths, `covers` kept) and
   no problems. It returns no tasks and a problem for each of: not a dict; empty `tasks`; more than `MAX_TASKS` tasks;
   a missing required field; an unknown field; a bad id; an id already in `existing_ids`; `covers` empty or naming an
   unknown requirement or listing one twice; a test file outside `tests/core/test_*.py` or with `..`; a scope entry
   that is a test path or absolute; `test_cmd` not `python -m unittest ` + exactly its test files; two tasks sharing a
   test file; a section over `SECTION_CAP`; bad `needs`.
3. **Sees only its inputs.** `build_prompt(spec_text, cov, rows, reasons)` contains the spec text, the coverage report
   (`cov.report()` text), each ledger row id and the reasons, and `ledger_rows(ledger)` marks a contract `completed`
   only when the ledger event log holds its `pass`.
4. **Writes nothing, on the real conductor path.** Using `DriftHarness` from `tests.core.test_planning_drift`: build a
   conductor with a Manager, set a pending re-plan with `core.drift.new_replan` + `drift.save`, and step. (a) A
   Manager that writes a file in its cwd: the step rejects the proposal; the pending re-plan's `notes` contain
   "read-only"; no task is added to the queue; the file is not in the layer worktree; the Manager's cwd is not the
   layer worktree and no longer exists afterwards. (b) A Manager that returns a valid `proposal("M1")`: task M1 is
   appended to the queue with its `covers`, and the re-plan id is recorded in the queue's `replans`.

Do not edit any existing test, drill or module.

## Task L1C_2: Troubleshooter answers: a dead end must name its alternative (2.6)

- files_in_scope: `core/bootstrap.py`
- test_files: `tests/core/test_l1c_troubleshooter.py`
- test_cmd: `python -m unittest tests/core/test_l1c_troubleshooter.py`
- covers: 2.6

Design §2: Troubleshooter is "Claude, acceptEdits, research tools | its own scratch worktree | fix.schema.json: fix, or
dead end plus alternative". Today `real_team` and `Conductor._troubleshoot` already give it Claude acceptEdits with
WebSearch/WebFetch and a throwaway scratch worktree, but a `dead_end` answer without an `alternative` is accepted and
written to `state/dead_ends.jsonl` (in `_troubleshoot` and in the capability job `_cap_job`). Build the missing check.

Add to `core/bootstrap.py` a module-level function:

```python
def trouble_problem(data) -> str | None:
    """None when a troubleshooter answer is usable; else a short reason."""
```

Rules, in this order: not a dict -> `"answer is not an object"`; `kind` not one of `"fix"`, `"dead_end"`,
`"suggestion"` -> `"unknown kind"`; `notes` not a string with non-whitespace text -> `"notes are empty"`; `kind ==
"dead_end"` and `alternative` not a string with non-whitespace text -> `"dead end without an alternative"`. A `fix` or
`suggestion` needs no alternative.

Use it in both places:
- `_troubleshoot`: when `r.ok` but `trouble_problem(r.data)` returns a reason, treat it like a failed run: append
  `f"(troubleshooter failed: {reason})"` to the task's `trouble_notes`, write nothing to `dead_ends.jsonl`, and update
  the task exactly as today (`troubleshot=True`, `fails_since=0`, `focus_s=0`, `troubleshoots+1`,
  `troubleshoot_pending=None`). Usable answers behave exactly as today.
- `_cap_job`: append to `dead_ends.jsonl` only when the answer is `ok`, its kind is `dead_end` and
  `trouble_problem` returns None. Everything else in `_cap_job` is unchanged.

Do not change `S_TROUBLE`, the prompts, or any other behaviour; all existing tests and drills must still pass.

Acceptance criteria (tests use `Harness` from `tests.core.test_bootstrap`, fake agents, a real conductor, driving a
task whose accepted test always fails so the troubleshooter is called, as in
`test_zero_progress_troubleshooter_notes_and_dead_end_are_prompted`):
1. `trouble_problem` returns None for `{"kind":"fix","notes":"n"}`, `{"kind":"suggestion","notes":"n"}` and
   `{"kind":"dead_end","notes":"n","alternative":"a"}`, and each reason above for a list, `{"kind":"other",...}`,
   blank notes, and a dead end with missing, empty or whitespace alternative or a non-string alternative.
2. Conductor path: a troubleshooter answering `{"kind":"dead_end","notes":"blocked"}` leaves no `dead_ends.jsonl`
   entry, and the task's `trouble_notes` end with `(troubleshooter failed: dead end without an alternative)`; one
   answering with an alternative is written to `dead_ends.jsonl` with that alternative and shown under
   `KNOWN DEAD ENDS:` in the next builder prompt.
3. Scratch worktree: a troubleshooter that writes `scratch.txt` in its cwd: its cwd differs from the layer worktree,
   and `scratch.txt` appears neither in the layer worktree nor in the task's next builder cwd.
4. Engine: `real_team({"agent_timeout_s": 60}).troubleshooter` is a `ClaudeAgent` with `permission_mode ==
   "acceptEdits"` whose `allowed_tools` include `"WebSearch"` and `"WebFetch"`.

## Task L1C_3: The drift keeper writes nothing, and a re-plan needs reasons (2.7)

- files_in_scope: `core/bootstrap.py`
- test_files: `tests/core/test_l1c_drift_keeper.py`
- test_cmd: `python -m unittest tests/core/test_l1c_drift_keeper.py`
- covers: 2.7

Design §2: Drift keeper is "Claude, read-only | may write nothing | drift.schema.json: ok, or re-plan plus reasons".
Today `real_team` makes it a ClaudeAgent in plan mode, but `Conductor._drift_check` runs it in the layer worktree
(`cwd` defaults to `self.wt`) and never checks for file edits (only commits are undone by `_guarded_run`), and a
`{"status":"replan"}` with no reasons is accepted. Build the missing enforcement, mirroring the Manager's
(`_replan_stage`: throwaway checkout + `self._changed(cwd=...)`).

Change only `Conductor._drift_check` in `core/bootstrap.py`:
- Run the drift keeper in a throwaway checkout of the layer worktree's HEAD:
  `tip = _git(self.wt, "rev-parse", "HEAD")`, `with self.trees.throwaway(tip) as dw:` call
  `self._call("drift_keeper", <same prompt as today>, S_DRIFT, cwd=dw)` and then `wrote = self._changed(cwd=dw)`
  inside the `with`. Keep the existing `except Capped` handling (reset the layer worktree if it exists, re-raise).
- If `wrote` is non-empty, the answer is unusable: log `"drift keeper is read-only but changed: " + ", ".join(wrote[:20])`
  with `self._log`, and handle it exactly like today's unusable result (`drift_failures` +1, saved; at 3, write
  `PAUSED` and ask Ben with kind `"replan"`; the error text in that question names the read-only violation). The
  status is not used, `drift_due` stays set.
- A usable answer must be `ok`, or `replan` with at least one reason that is non-blank text after the existing
  conversion (a string reason becomes a one-item list). `{"status":"replan"}` with missing, empty or all-blank reasons
  is unusable, handled the same way (error text `"replan without reasons"`).
- Everything else is unchanged: a stall trigger still forces a re-plan even when the keeper says `ok`, the re-plan is
  saved durably before `drift_due` is cleared, and without a Manager a re-plan pauses and asks Ben.

All existing tests and drills must still pass (`test_bootstrap` uses `"reasons":"design drift"`, which stays valid).

Acceptance criteria (tests use `DriftHarness` from `tests.core.test_planning_drift`, real conductor, fake agents,
finishing one task so a drift check runs):
1. The drift keeper's cwd is not the layer worktree and no longer exists after the step; its prompt contains
   `COVERAGE` and `DESIGN:`.
2. A keeper that writes `drift-note.txt` in its cwd and answers `ok`: the file is not in the layer worktree, the
   queue keeps `drift_due` true with `drift_failures == 1`, and after 3 such checks `state/PAUSED` exists and a
   question of kind `replan` was asked (an email went out) whose body mentions read-only.
3. A keeper answering `{"status":"replan","reasons":[]}` or `{"status":"replan","reasons":["  "]}` or
   `{"status":"replan"}`: no re-plan is created (`drift.load(state)["replan"]` is None or the drift state has none),
   `drift_failures` rises; `{"status":"replan","reasons":["off course"]}` creates a re-plan whose reasons include
   "off course" and clears `drift_due`.
4. A keeper answering `ok` with no write clears `drift_due` and sets `drift_failures` to 0.
5. `real_team({"agent_timeout_s": 60}).drift_keeper` is a `ClaudeAgent` with `permission_mode == "plan"` and
   `allowed_tools == ["Read", "Glob", "Grep"]`.

## Task L1C_4: 1C gate: coverage must rise, re-plan triggers, a fresh Manager sees the ledger only (3.7, 7.7)

- evidence: true

- files_in_scope: `core/drift.py`, `core/coverage.py`
- test_files: `tests/core/test_l1c_gate.py`
- test_cmd: `python -m unittest tests/core/test_l1c_gate.py`
- covers: 3.7, 7.7

This is an evidence task (R63) and the 1C gate. It runs after L1C_1 to L1C_3 are merged; the builder changes
nothing. The tests must pass on the current code and fail on empty `core/drift.py` and `core/coverage.py`.

Design §3.7: "Drift keeper runs after every merge. Coverage must rise. If there's no gain in 3 merges, or no merge in
2 active hours, it re-plans." Design §7 gate for 1C: "Drills: coverage must rise; re-plan triggers; a fresh Manager
sees the ledger only". These drills exist in `drills/run_drills.py` as `drill_11`, `drill_12`, `drill_13`, listed in
`DRILLS` as `(11, "1C: Coverage must rise", ...)`, `(12, "1C: Re-plan triggers", ...)`,
`(13, "1C: A fresh Manager sees the ledger only", ...)`.

Tests must check:
1. **Gate drills.** Import `drills.run_drills` (run from the repo root, as `test_cmd` does) and assert `DRILLS` holds
   entries 11, 12 and 13 with exactly those names, and that calling `drill_11()`, `drill_12()` and `drill_13()` each
   returns a non-empty string without raising.
2. **Drift keeper after every merge (real conductor).** With `DriftHarness`, two tasks covering requirements 1.1 and
   1.2: after each task is finished (`finish`), the drift keeper has been called once more (2 prompts in total), each
   prompt holds the coverage map, and `drift.load(state)["history"]` records both merges with `gain` True and the
   score rising (`Fraction(history[1]["score"]) > Fraction(history[0]["score"])`).
3. **Coverage rules (`core/coverage.py`).** `parse_requirements` numbers list items and table body rows per `## N.`
   section (`N.k`), skips code blocks, headers and nested items, gives a section with no items id `N`, and raises
   ValueError on a repeated section number. `compute` + `Coverage.status/score/covered/report`: unclaimed, open,
   partial (k/n credit as an exact Fraction), covered only when every claimant is verified. `verified_done` needs both
   queue `done` and a ledger `pass` (use a real `core.ledger.Ledger` with a `roles.json`, as drill 11 does);
   `claims` drops duplicates and non-string lists.
4. **Stall rules (`core/drift.py`).** `record_merges` counts each merge once, ignores `deferred`, sets gain from the
   score, resets `no_gain` and `auto_replans` on gain, leaves `no_gain` unchanged when the score function is None,
   and moves `active_mark`; `no_gain_due(d, 3)` is False at 2 and True at 3; `idle_due(d, active, 7200)` is False
   just under and True at 7200 active seconds after the mark; `restart_window` zeroes `no_gain` and moves the mark;
   `adopt` keeps the pending (last) mark uncounted when a drift check is due; `new_replan` numbers re-plans R1, R2
   and caps reasons; `Activity.add` ignores zero, negative, non-finite and bool values and `total` survives a
   corrupt file; `load` returns None for a missing or corrupt `drift.json`.

Do not edit any existing test, drill or module.
