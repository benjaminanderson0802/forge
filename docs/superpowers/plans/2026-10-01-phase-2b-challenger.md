# Phase 2B: the Challenger (implementation plan)

> Source of truth: `docs/specs/phase-2-design.md` §2 and §4 (D-040, proposed). Builds on Layer 1 (`docs/specs/bootstrap-conductor.md` R1–R67, E1–E5) and on P2A (`docs/superpowers/plans/2026-10-01-phase-2a-auditor.md`), whose changes to `core/ledger.py`, `core/bootstrap.py` and `core/roles.py` are kept intact by every task here. Scoring is P2C, not this plan.

## Goal

Every "impossible" verdict a Claude role gives (an accepted builder blocker, a Troubleshooter dead end, a task's final R5 `blocked` verdict) is attacked by a Codex Challenger in a scratch worktree at the task's tests commit. Only plain code decides who won. The Challenger's edits are discarded; the Builder builds the route itself, tests first.

## Conformance notes (R45)

- **Off switch keeps Layer 1 intact.** Every challenger behaviour is active only when `getattr(self.team, "challenger", None) is not None`. `real_team` always sets it; the fake six-role teams in the existing tests do not, so every current test in `tests/core/` keeps its exact behaviour.
- **R1:** proofs run `test_cmd` only through `Conductor._run_tests` (no shell). Every new test_cmd is `python -m unittest <its test file>`.
- **R9/R14:** every conductor write (queue fields, `challenges.jsonl`, ledger) happens between agent runs, never during one.
- **R19:** notes, routes, history and diffs stored on tasks are capped (`NOTE_CAP`, 20000 characters for diffs, short lists).
- **R37/R38/R42/R54 (never a stall):** a capped, held, stopped or unready Challenger on a builder blocker withdraws the attempt (`withdraw`, not counted). Pending dead ends and blocked verdicts stay pending, are picked before other work like `troubleshoot_pending`, and keep the runs already completed so a claim never gets more than `challenge_runs` runs.
- **D-020:** the Challenger is Codex (`workspace-write`, `--ephemeral` fresh session) and never falls back to Claude.
- **D-031:** rejected blocker claims keep today's path; the Challenger only attacks claims that passed Layer 1's checks.
- **Ledger (D-001):** `challenge` is core-only, any contract status, no transition. A rescued blocked task needs one more transition the ledger already has: `unpark`. A core `unpark` is accepted only with a verified, overturned `blocked` challenge event for the same contract, once per event, and it raises `max_attempts` so the budget guard does not re-park at once.

## T2Ba: Ledger `challenge` action and evidence-backed rescue `unpark`

Add the ledger action `challenge` and an evidence-backed core `unpark` to core/ledger.py (a protected file; D-037 standing approval). Design: docs/specs/phase-2-design.md §2 (challenge outcomes are applied by forge-core, role core) and §4 (Records; the blocked-verdict rescue). No dependency on other tasks in this plan. Keep every change P2A made to core/ledger.py (its `audit` action) intact.

1. `ACTIONS["challenge"] = ({"core"}, None, None)`: only role core may apply it, from any contract status, with no transition. Handle it in its own branch of `apply` (like `run_report`), before the generic branch:
   - Payload validation (raise `Rejected` naming the field): `target` in {"blocker", "dead_end", "blocked"}; `claimant` in {"builder", "troubleshooter"}; `verdict` in {"overturned", "stands", "unconfirmed"}; `proof` is "patch", "capability" or None (an absent key counts as None); `route` is a str of at most 2000 characters (absent counts as ""); `run_ids` is a non-empty list of at most 10 str; optional `outcomes`: when present, a list of the same length as `run_ids` whose items are each one of "verified_overturn", "unverified_overturn", "stands", "stands_no_evidence", "unusable", "interrupted".
   - Contract: if `contract_id` exists, the contract is left exactly as it was (status, attempts, max_attempts, commit, tokens_used unchanged; the budget guard is not run) and the event's `result_status` is its current status. If it does not exist, the event is accepted only when `contract_id` starts with `capability:` and `target` is "dead_end" (a Troubleshooter capability-job dead end has no task contract); its `result_status` is None. Any other unknown contract is `Rejected("no contract <id>")`.
   - It never adds a note (never `false_claim`) and never changes run reports, test runs or the spec state. The kill switch, the frozen-spec refusal (role core is not exempt), the hash chain and proposal-id idempotency apply exactly as for every other action.
2. `Ledger.challenges(contract_id: str | None = None) -> list[dict]`: every `challenge` event in log order as `{"proposal_id", "contract_id", **payload}`, filtered by `contract_id` when given.
3. Rescue unpark: `ACTIONS["unpark"]` roles become {"human", "core"}. A human unpark is unchanged. A core unpark is accepted only when the payload has `challenge`, the proposal_id of an earlier event in this ledger's log whose action is `challenge`, on the same contract, with payload target "blocked" and verdict "overturned", and no earlier `unpark` event whose payload `challenge` names that same proposal_id; and `extra_attempts`, an int (not a bool) from 1 to 6. Otherwise `Rejected`. Effect: status parked -> open and `max_attempts = attempts + extra_attempts`, so the budget guard does not re-park it at once. A core unpark from any status other than parked is Rejected, as today.
4. Replay: `derive()`, `rebuild()` and `reconcile()` reproduce both actions exactly (the checks read the ledger's own event log, which during replay holds exactly the earlier events).
5. Add one line for each rule to the module docstring's "Rules enforced" list.

Acceptance criteria (tests/core/test_p2b_ledger_challenge.py; temporary ledgers whose roles.json maps forge-core->core, forge-auditor->auditor, forge-executor->executor, forge-manager->manager, ben->human):
- forge-core applies a valid challenge to contracts in open, claimed, submitted, parked and done (done built with the normal create/claim/run_report/submit/test_run/pass sequence): each contract dict is identical before and after, the event's result_status equals that status and its role is core;
- the auditor, executor, manager and human identities are Rejected for challenge;
- each invalid field (bad target, claimant, verdict or proof; route over 2000 characters; empty or non-list run_ids; outcomes of the wrong length or with an unknown item) is Rejected and `snapshot()` is unchanged;
- challenge on unknown contract "T9" is Rejected; on "capability:docker" with target dead_end it is accepted with result_status None, and with target blocker it is Rejected;
- re-applying the same proposal_id returns status "duplicate"; `false_claims()` is unchanged; `challenges()` returns the events in order and filters by contract;
- core unpark is Rejected without `challenge`, with a challenge id of another contract, of target blocker, of verdict stands, with extra_attempts 0, 7 or True, and on a second use of the same challenge; it is accepted on a contract parked after 6 failed attempts, giving status open and max_attempts = attempts + 2, after which a claim by forge-executor succeeds; a human unpark of a parked contract is still accepted;
- after these events `reconcile()` returns False on an intact cache and `derive()["contracts"]` equals `contracts()`.

## T2Bb: Challenger role plumbing

Challenger role plumbing in core/bootstrap.py, core/roles.py and the new protected role file agents/challenger.md (D-037). Design §2 and §4. No dependency inside this plan. Keep P2A's changes (team.auditor, S_AUDIT, the auditor in SMOKE_ROLES) intact; if P2A already created an extra-roles mechanism for the auditor in core/roles.py or Team, add the challenger to that same mechanism instead of a second one.

1. Schema: `S_CHALLENGE = _obj({"verdict": {"type": "string", "enum": ["overturned", "stands"]}, "route": _STR, "tried": _STRS, "error": _STR, "proof": {"type": "string", "enum": ["patch", "capability"]}}, ["verdict"])`. Only `verdict` is required by the shape check; plain code later judges missing fields (T2Bc).
2. Roles: core/roles.py keeps `ROLE_NAMES` and `DEFAULTS` exactly the six Layer 1 roles (tests/core/test_roles.py pins them). Add `EXTRA_ROLE_NAMES` (containing "challenger", plus "auditor" if P2A put it there) and `EXTRA_DEFAULTS["challenger"]`, whose first line is "You are the CHALLENGER." and which says: your job is to find a working route; you win only if plain code verifies it; you work only in your scratch worktree, which is discarded; never edit test files; answer "overturned" with proof "patch" (your edits make the task's tests pass, or fail less) or proof "capability" (the capability's readiness check passes now), or "stands" with at least 2 routes you tried that differ from the claimant's, plus the real error. `role_text` accepts every name in ROLE_NAMES + EXTRA_ROLE_NAMES (same file rules; the default comes from DEFAULTS or EXTRA_DEFAULTS); unknown names still raise ValueError. agents/challenger.md holds the full instructions in the same shape, first line "You are the CHALLENGER.", LF line endings.
3. Team: `challenger` is a class attribute `challenger = None` WITHOUT a type annotation, so it is not a dataclass field: `Team(<the six Layer 1 roles>)` keeps working and `vars()` of such a Team gains no key (tests/core/test_live_run.py counts 6 smoke calls from `vars(team)`). `real_team(limits)` sets `team.challenger = CodexAgent(limits.get("agent_timeout_s", 1800), sandbox="workspace-write")`. 4. Smoke (R23/R29): `SMOKE_ROLES["challenger"] = (S_CHALLENGE, True, '{"verdict": "stands", "route": "smoke", "tried": ["a", "b"], "error": "smoke", "proof": "patch"}')`, a writer role that must create smoke.txt containing ok and change nothing else. `smoke()` skips any SMOKE_ROLES role whose team member is None (with or without `call`), so a fake six-role team still makes exactly 6 calls.
5. Prompt plumbing for later tasks: `_prompt_blocks` adds KNOWN DEAD ENDS for role "challenger" as it does for builder and troubleshooter. `_guarded_run` sets `self.last_run_id = run_id` before the agent is launched. The builder prompt in `_build_stage` adds, after TROUBLESHOOTER NOTES, `"\nCHALLENGER ROUTE:\n"` plus one `"- <route>"` line per entry of the task's `challenger_routes` list (its last 3 entries, each capped at NOTE_CAP) when that list is non-empty.
6. Failure plumbing: the `fail()` closure in `_build_stage` stores on the task, before it resets the worktree, `last_attempt_diff = self._attempt_diff(twt, base)[:20000]` (on RuntimeError or OSError the value is `"(diff unavailable: <error>)"`). `_after_failure` and `fail()` gain `suppress_handoff: bool = False`: when True the failure is recorded exactly as now (notes, fail_signatures, fails_since) but neither the Troubleshooter call nor the block decision happens.

## T2Bc: `core/challenge.py`, plain-code proof verification and bounds

Create core/challenge.py: pure, standard-library functions (plus `core.readiness.NAME_RE`) that decide every Challenger outcome. Design §4 (an overturn must be proven by plain code; a claim stands only with evidence; bounds). No dependency inside this plan; nothing here launches an agent, runs git or writes files. Callers (T2Bd, T2Be) pass the test runs and checks in as callables.

- `RUN_OUTCOMES = ("verified_overturn", "unverified_overturn", "stands", "stands_no_evidence", "unusable", "interrupted")`.
- `norm_route(text) -> str`: casefold, collapse every whitespace run to one space, strip, then strip surrounding quotes/backticks and trailing `.;:,!`.
- `stands_evidence(answer: dict, claimant_routes) -> str | None`: None when the stands answer has at least 2 distinct normalized `tried` routes (non-empty strings) that are not equal to any normalized claimant route, and a non-empty (after strip) str `error`. Otherwise a reason starting "stands without evidence: " ("fewer than 2 distinct routes not copied from the claimant" or "no error").
- `parse_unittest(output: str) -> dict`: `{"ran": int | None, "failures": int, "errors": int}`. `ran` is the last `^Ran (\d+) tests? in` match (multiline), else None; failures and errors come from the last `^FAILED \((...)\)` line (`failures=N`, `errors=N`, other keys ignored), else 0.
- `run_passed(code, output, timed_out) -> bool`: not timed out, exit 0 and `ran >= 1`.
- `scope_problem(changed, files_in_scope, test_files) -> str | None`: paths normalized (backslashes to `/`, leading `./` removed). Empty changed -> "no changes"; any test file -> "touched test files: a, b"; any path matching no `fnmatch` pattern of files_in_scope -> "out of scope: a, b"; else None.
- `verify_patch(changed, files_in_scope, test_files, run_patched, run_baseline) -> tuple[bool, str]`: each run callable returns `(code, output, timed_out)`. A scope problem fails without running anything. Then `run_patched()`: if `run_passed` -> (True, "tests pass (Ran N)"). Otherwise, if the patched run timed out or ran no test -> (False, ...). Else `run_baseline()` is called (at most once, only here): a baseline that timed out or ran no test -> (False, "baseline run unusable"). Verified (True, "progress: failures+errors B -> P") only when patched failures+errors is strictly less than the baseline's AND patched ran >= baseline ran (a run that executes fewer tests can't show progress); else (False, "no progress: failures+errors B -> P").
- `verify_capability(capability, check) -> tuple[bool, str]`: `capability` must be a str matching `readiness.NAME_RE`, else (False, "no capability named"). `check(name)` returns the fresh capability-map entry or None. Verified only when the entry is a dict with `ok is True`; None -> (False, "no check exists for <name>"); otherwise (False, "<name> still broken: <detail>").
- `judge_run(ok, answer, claimant_routes, verify) -> dict`: `{"outcome", "verdict", "route", "tried", "error", "proof", "detail"}`. Not ok, a non-dict answer, or a verdict outside overturned/stands -> "unusable". overturned: proof "patch" or "capability" -> `verify(proof)` -> verified_overturn or unverified_overturn with its detail; any other proof -> unverified_overturn ("unknown proof"). stands: `stands_evidence` None -> "stands", else "stands_no_evidence". route is the stripped str route capped at 2000 characters ("" when absent); tried is the list of str routes; exceptions from `verify` propagate.
- `decide(outcomes, limit) -> str | None`: limit = max(1, int(limit)). "verified_overturn" present -> "overturned"; else "stands" present -> "stands"; else len(outcomes) >= limit -> "unconfirmed"; else None (another run is allowed). "interrupted" counts toward the limit.
- `claim_key(target, subject, claim) -> str`: sha256 hex of `json.dumps([target, subject, claim], sort_keys=True, default=str)`.
- `ledger_payload(target, claimant, verdict, runs) -> dict`: runs are dicts with run_id, outcome, route, proof. Returns `{"target", "claimant", "verdict", "proof", "route", "run_ids", "outcomes"}`: proof and route come from the first run whose outcome is verified_overturn (overturned) or stands (stands; proof None); for unconfirmed, proof None and route "". route capped at 2000.

Acceptance criteria (tests/core/test_p2b_challenge_proofs.py; real temporary files are not needed, callables are stubs that count their calls):
- norm_route equates "Use  Datetime." and "use datetime";
- stands_evidence: two fresh routes plus an error -> None; routes that differ from the claimant's only in case, spacing or a trailing period are copies; one fresh route, duplicates of one route, or an empty or missing error each give the matching reason;
- parse_unittest on real unittest outputs ("OK", "FAILED (failures=2, errors=1)", "FAILED (errors=1, skipped=3)", no Ran line);
- run_passed is False for exit 0 with "Ran 0 tests", for a timeout, and for a non-zero exit;
- verify_patch: a change to a test file, an out-of-scope file, or no change is rejected and neither runner is called; a passing patched run is verified and the baseline runner is not called; failures+errors 3 -> 1 with the same Ran count is verified; 1 -> 1, 1 -> 2, and fewer tests run are not; a timed-out patched run is not; the baseline runner is called at most once;
- verify_capability: entry ok True verified; ok False, None, and an invalid name not verified;
- judge_run covers all six outcomes except interrupted, plus an unknown proof and ok=False;
- decide: ["unusable"] with limit 2 -> None; ["unusable", "unverified_overturn"] -> "unconfirmed"; ["stands_no_evidence", "stands"] -> "stands"; ["unusable", "verified_overturn"] -> "overturned"; limit 0 behaves as 1; ["interrupted", "unusable"] -> "unconfirmed";
- claim_key is stable across dict key order and differs by target and subject; ledger_payload builds the exact dict for each verdict.

## T2Bd: The challenge runner and the builder-blocker target

The generic challenge runner in core/bootstrap.py and its first target, accepted builder blockers. Design §2 (Challenger runs in its own scratch worktree, edits discarded), §4 (brief, outcomes for a builder blocker, never a stall, records). Builds on T2Ba (ledger `challenge`), T2Bb (S_CHALLENGE, team.challenger, `last_run_id`, `_prompt_blocks`, `challenger_routes`, `suppress_handoff`) and T2Bc (core/challenge.py). All behaviour here is active only when `getattr(self.team, "challenger", None) is not None`; otherwise the code paths are exactly today's.

Conductor methods:
- `_challenger_on() -> bool`; `_challenge_limit() -> int` = max(1, int(self._int_limit("challenge_runs", 2))).
- `_challenge(*, target, claimant, cid, t, capability, claim, claimant_routes, tests_commit, diff, history, runs, save) -> dict`. `t` is the task dict or None (capability dead end, T2Be); `runs` is the list of runs already completed for this claim; `save(runs)` persists it. Loop while `challenge.decide([r["outcome"] for r in runs], limit)` is None: build the prompt; `with self.trees.throwaway(tests_commit) as sw:` run `self._call("challenger", prompt, S_CHALLENGE, cwd=sw, scratch=True)`; append `{"run_id": self.last_run_id, "outcome": "interrupted"}` and call `save(runs)` at once (a run is counted before it is verified); then `challenge.judge_run(r.ok, r.data, claimant_routes, verify)` replaces that entry (run_id, outcome, route, tried, error, proof, detail; strings capped at NOTE_CAP) and `save(runs)` again. Capped, NotReady, Stopped and Tampered propagate; completed runs are already saved, so a resumed claim continues with the remaining runs only. `verify("patch")`: with no task -> (False, "no task tests"); else `challenge.verify_patch(self._changed(cwd=sw), files_in_scope, test_files, lambda: self._run_tests(t, cwd=sw), baseline)`, where baseline runs `self._run_tests(t, cwd=bw)` in a separate `self.trees.throwaway(tests_commit)`. `verify("capability")`: `challenge.verify_capability(capability, check)` where check(name) is `self._refresh_readiness(names={name}, force={name}).get(name)` when name is in self.checks or self.probes, else None (a fresh check, ignoring every TTL). Once decided: payload = `challenge.ledger_payload(target, claimant, verdict, runs)`; `self._apply(f"challenge-{runs[0]['run_id']}", "challenge", cid, "forge-core", payload)`; append one JSON line to state/challenges.jsonl: `{"task": t["id"] or None, "capability", **payload, "runs": runs, "event": <pid>, "at": clock iso}`. Return `{"verdict", "proof", "route", "run_ids", "runs", "event"}`. The scratch worktree is removed by the throwaway context; nothing the Challenger wrote is committed anywhere.
- `_challenge_prompt(...)`: role_text(repo, "challenger"); "Your job is to find a working route. You win only if plain code verifies your route."; the target in words; `self._task_prompt(t)` (or the capability name); "CLAIM:" plus the claim as JSON (capped 8000); "CLAIMANT ROUTES (already tried; the routes you list in tried must differ from these):" one "- " line per route; "FAILURE HISTORY:" lines when history is given; "CAPABILITY MAP ENTRY for <cap>: <entry JSON | no evidence yet | no automatic check exists>" (as `_check_blocker` shows it; for no capability, the entries of the task's needs or "(no capability named)"); "THE ATTEMPT'S DIFF:" plus diff (capped 40000); "EARLIER CHALLENGER RUNS ON THIS CLAIM:" with each run's outcome and detail when runs exist; that it works in a scratch worktree at the task's tests commit whose edits are checked by plain code and then discarded, and must never edit test files; the JSON answer format. KNOWN DEAD ENDS are appended by `_call` (T2Bb).

Builder-blocker target, in `_build_stage` right after `_check_blocker` returns None (accepted): claim = summary, tried, error, capability, meanwhile; key = `challenge.claim_key("blocker", tid, claim)`; runs = the task's `blocker_challenge["runs"]` when its `key` equals key, else []; save stores `blocker_challenge={"key", "runs"}`; tests_commit = the task's `tests_commit` (the commit Stage A made, never the layer HEAD or the build base; fall back to base only if the field is missing); diff = `self._attempt_diff(twt, base)`; claimant "builder"; cid the task's contract id.
- Capped or NotReady (stopped, held, unready): apply `withdraw` (forge-core), reset the task worktree to base and re-raise: the attempt is not counted, no easy-out, no needs, no failure signature (R54). `blocker_challenge` keeps the completed runs; the next attempt with the same claim resumes them, a different claim replaces them.
- overturned: `blocker_challenge` cleared; `_record_easy_out(tid, tag, cid, "blocker overturned by challenger: <route>", d, summary)`; append the route to the task's `challenger_routes` (keep the last 3); then `fail(<that reason>, "easy-out", suppress_handoff=True)`. No needs entry, no Troubleshooter handoff and no block decision in this step, even when the attempt used up its focus time (the D-026 check at the start of the next attempt still applies).
- stands: cleared; the task notes gain "challenger: blocker stands (runs <ids>): tried <a; b>; error <e>" (capped); then today's accepted path unchanged (needs, notes, immediate Troubleshooter handoff).
- unconfirmed: cleared; `fail("blocker unconfirmed: challenger gave no evidence", "blocker-unconfirmed", handoff=exceeded, focus=exceeded)`: no needs entry, not an easy-out, the normal focus rule applies.

Acceptance criteria (tests/core/test_p2b_blocker_challenge.py; BlockerHarness fakes, `c.team.challenger = FakeAgent(script, provider="codex")` set after init, a controlled clock):

- a patch that edits a test file, and a patch whose tests fail no less than at the tests commit, are unverified; two such runs give exactly 2 challenger runs and the attempt fails with "blocker unconfirmed: challenger gave no evidence", no needs added, no easy-out line, ledger verdict unconfirmed with outcomes ["unverified_overturn", "unverified_overturn"];
- stands with two fresh routes and an error: needs gains the capability, the troubleshooter is called, notes carry the challenger evidence, ledger verdict stands; stands copying the builder's tried routes counts as stands_no_evidence;
- proof capability: the fake docker check is called again with force (its call counter rises even though its entry is fresh) and returns ok -> overturned;
- never a stall: the first challenger run is unusable and the codex meter goes over its cap during it; the step returns "capped", the ledger shows withdraw (contract attempts unchanged), no easy-out, no needs, blocker_challenge holds 1 run; after the cap lifts the builder repeats the same claim and exactly 1 more challenger run happens (2 in total) -> unconfirmed;
- fresh session: with core.agents.launch patched to capture its args, `real_team({}).challenger.run("x", tmp, S_CHALLENGE)` passes "--ephemeral" and "-s", "workspace-write";
- the prompt contains the brief sentence, the task section, the claim's tried routes and error under CLAIM:, "CLAIMANT ROUTES" with the builder's routes, "CAPABILITY MAP ENTRY for docker", "THE ATTEMPT'S DIFF" mentioning feat.py, and KNOWN DEAD ENDS when present;
- with team.challenger None, an accepted blocker behaves exactly as today (no challenger call, needs and handoff).

## T2Be: Dead-end and blocked-verdict targets, pending challenges, rescue

The two remaining Challenger targets in core/bootstrap.py: Troubleshooter dead ends (task troubleshoots and capability fix jobs) and a task's final R5 blocked verdict, with pending handling and the bounded rescue. Design §4 (what it attacks, its brief, outcomes for a dead end and a blocked verdict, never a stall). Builds on T2Ba (challenge event, core rescue unpark), T2Bb (team.challenger, last_attempt_diff, challenger_routes, CHALLENGER ROUTE), T2Bc and T2Bd (`_challenge`, `_challenge_prompt`). With `team.challenger` None every path below is exactly today's.

Task dead ends: in `_troubleshoot`, a `dead_end` answer is no longer appended to dead_ends.jsonl; its notes still go to trouble_notes. It is appended to the task's list `dead_end_pending`: `{"notes", "alternative", "tests_commit": the task's tests_commit, "diff": the task's last_attempt_diff (the failed attempt that led here, kept by T2Bb before cleanup; "(no attempt diff recorded)" only when no attempt ever stored one), "runs": [], "at"}`. `_troubleshoot` itself launches no Challenger (so the R38 handling in `_after_failure` never confuses a challenger outage with a troubleshooter outage).

Final blocked verdicts: new `_final_block(tid, why)` replaces `_block` at exactly two call sites, the R5 block in `_after_failure` (rounds >= 3) and the parked-contract block in `_build_stage`. Test-writer rejections (R4), plan rejections (R45) and the R65 evidence-rewrite bound keep calling `_block`: they are not an "impossible" verdict by a Claude role. `_final_block`: challenger off -> `_block(tid, why)`; the task's `challenge_rescues` >= `_int_limit("challenge_rescues", 1)` -> `_block(tid, why + "\n\nCHALLENGER: no rescue left (used N of N); last challenge: <evidence>")` with no new run; otherwise store `blocked_pending = {"why", "tests_commit", "diff": last_attempt_diff, "history": the task's last 10 notes + last 5 trouble_notes (the failure history), "claimant_routes": its last 5 trouble_notes, "runs": [], "at"}` (each entry capped at NOTE_CAP) and ask nothing yet.

Pending first (R38 style): `_stage_role` returns "challenger" for a tests_ok task with `dead_end_pending` or `blocked_pending` (troubleshoot_pending still wins); `_pick_tasks` puts such tasks with the pending troubleshoots, so an unready challenger records `waiting_on` and the task waits. `_build_stage`, after the troubleshoot_pending check, runs the oldest pending dead end, else the blocked verdict, and returns (one stage per step). Each uses `_challenge` with the stored tests_commit and diff (never the current layer HEAD), claimant "troubleshooter", cid the task's contract id, and `save` writing `runs` back into that pending record, so completed runs survive a deferral. Capped, NotReady and Stopped leave the pending record (with its runs) in place and propagate as usual.
- Dead end: claim `{"dead_end_notes", "alternative"}`, claimant_routes [notes]. overturned -> removed from pending, never written to dead_ends.jsonl, route appended to challenger_routes, note "dead end overturned by challenger: <route>"; stands -> removed and appended to dead_ends.jsonl as `{"task", "notes", "alternative", "challenged": <run_id of the deciding run>}`; unconfirmed -> removed, nothing written, note "dead end unconfirmed: challenger gave no evidence" (the notes stay in trouble_notes only).
- Blocked verdict: claim `{"blocked": why}`, history and claimant_routes from the record. overturned -> if the contract is parked, apply `unpark` (forge-core) with `{"challenge": <the challenge event pid>, "extra_attempts": CHALLENGE_RESCUE_ATTEMPTS}` (a module constant, 2); a refused unpark falls back to `_block(tid, why + "; rescue refused by the ledger")`. Then status tests_ok, blocked_pending None, challenge_rescues + 1, fails_since 0, fail_signatures [], focus_s 0, the route in challenger_routes and in notes. No question to Ben. stands or unconfirmed -> blocked_pending None and `_block(tid, why + "\n\nCHALLENGER (<verdict>; runs <ids>): route <route>; tried <a; b>; error <e>")`, so the blocked question carries the challenger's evidence.

Capability dead ends: in `_cap_job`, a dead_end answer is appended to the queue-level list `cap_dead_end_pending` (`{"capability", "notes", "alternative", "detail", "runs": [], "at"}`) instead of dead_ends.jsonl. `_route_capabilities`, right after `_resolve_caps`, runs the oldest one when the challenger is ready and returns "worked"; when it is unready (or NotReady is raised) it stays pending and routing continues; Capped propagates and it stays pending. It uses `_challenge` with t None, cid "capability:<name>", capability = name, the scratch tree at the layer tip, the diff text "(capability fix job: no task attempt)" and the job's detail in the claim. Only a capability proof can verify (a fresh forced readiness check). overturned -> not written; the route goes to challenger_routes of every task whose needs include the capability; stands -> dead_ends.jsonl gains `{"capability", "notes", "alternative", "challenged": <run_id>}`; unconfirmed -> nothing written, kept in cap_routing.json under that capability's `unconfirmed_dead_ends` (last 5).

Acceptance criteria (tests/core/test_p2b_pending_challenges.py; fakes, controlled clock, `c.team.challenger` set after init):
- a troubleshooter dead end leaves dead_ends.jsonl unchanged and puts one dead_end_pending entry whose tests_commit is the task's tests_commit and whose diff mentions the failed attempt's feat.py; the next step runs the challenger, not the builder; its prompt holds the dead-end notes, the alternative, CLAIMANT ROUTES with the notes, and the diff; its cwd HEAD is the stored tests_commit even after the layer branch moved;
- dead-end outcomes: overturned -> no dead_ends.jsonl line, challenger_routes holds the route, ledger challenge target dead_end, claimant troubleshooter; stands with evidence -> one line with "challenged" equal to the deciding run id; unconfirmed -> no line and the unconfirmed note;
- R5 block: a task with troubleshoots 3 whose second failure since the last round comes in asks no blocked question and stores blocked_pending; the next step's challenger prompt contains "FAILURE HISTORY:" with those failure notes and "CLAIMANT ROUTES" with the trouble notes, plus the stored diff;
- parked contract (6 failed attempts): no question; overturned -> ledger unpark by forge-core naming the challenge event, contract open with max_attempts = attempts + 2; status tests_ok, counters reset, challenge_rescues 1; the following step runs the fake builder and its ledger claim is applied;
- stands and unconfirmed: the task is blocked with exactly one blocked question whose body contains "CHALLENGER", the run id, the tried routes and the error; a final block after a rescue runs no challenger and the question says "no rescue left";
- never a stall: with codex unready the task records waiting_on with codex and the pending record stays; one finished run followed by Capped on the next launch leaves that run in the record, and after the cap lifts exactly one more run happens (2 in total);
- capability dead end: dead_ends.jsonl unchanged after the job and cap_dead_end_pending holds it; a later routing step runs the challenger; a forced check now ok -> overturned and no line; stands -> a line with "capability" and "challenged"; a patch proof is unverified; ledger contract_id "capability:<name>";
- all three targets: a builder blocker, a dead end and a blocked verdict each produce one challenge event with targets blocker, dead_end and blocked;
- with team.challenger None: dead ends are written at once and the R5 and parked paths ask the blocked question at once, as today.
