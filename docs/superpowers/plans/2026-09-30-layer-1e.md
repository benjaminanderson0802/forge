# Layer 1E: Ben's channel (plan)

> Implements `docs/specs/layer-1-design.md` §6 and the "Input for 1E: ChatGPT Dots" note (D-021 to D-024), on top of the
> bootstrap conductor's email code. Every rule in `docs/specs/bootstrap-conductor.md` R18-R40 keeps holding: all mail
> still goes through `_send` (budget, KILL, Message-IDs), replies still need the owner address plus qid and code.

## Goal

Ben hears from Forge less often and more usefully: urgent things at once, everything else in one morning digest,
nothing at night except emergencies. He can see and answer the whole queue on a local page, and stop Forge from it.

## Pieces

1. **`core/channel.py` (new, plain code, stdlib only)**
   - `INSTANT_KINDS` (D-023): `gate`, `replan`, `capability`, `spend`, `customer`, `tamper`. Everything else
     (for example `blocked`, `merge`) goes to the digest. Halt alerts (`halt=True`) are emergencies.
   - `DEFAULTS`: what Forge does while a question of each kind is unanswered (D-023: every question has a default).
   - `is_quiet(local_dt, start, end)`: 23:00-07:00 by default.
   - `queue_items(questions)` and `write_queue(path, questions)`: `queue.jsonl`, one open question per line with
     `id, kind, question, default, deadline, status, via`. It is a view derived from `questions.json` (the one source
     of truth), rewritten atomically whenever `questions.json` is written. `deadline` is null unless the asker sets
     one: no default is ever applied automatically in 1E.
   - `build_digest(...)`: one email listing every open question (with its default and an answer line
     `[Forge Q-<qid> <code>]` / `mailto:` link), task counts, and mail and token use. Capped at `BODY_CAP`.
   - Answer drop folder `channel/in/*.json` (`{qid, code, answer, source}`): `drop_answer()` writes one atomically,
     `take_answers()` reads and removes them (at most 50 per call, small files only). This is the **one interface
     point for any non-email channel**: the status page uses it now; a future Dot bridge would use it too
     (read `queue.jsonl`, drop answers). Forge validates every dropped answer exactly like an email reply (open
     question, matching code). The Dot trial itself is not built (it needs external setup).
2. **Conductor wiring (`core/bootstrap.py`, additive)**. Active only when `limits` has `digest_hour` (so the policy
   is off until Ben switches it on after a watched cycle, D-035; existing behaviour and tests are unchanged):
   - `_ask`: a kind outside `INSTANT_KINDS` (and not a halt) is stored held for the digest, never emailed alone.
   - `_send` and `_notice_once`: during quiet hours nothing but a halt alert is sent (a held question stays
     undelivered and is retried after 07:00 by the existing R7 retry).
   - `_channel_tick()` each step: at most one digest per local day at/after `digest_hour`, only when there is
     something to report; plus an early "stalled" digest (at most once per 12 hours) when no task can run and at
     least one held question has not been in a digest yet. Each digest attempt is recorded before sending.
   - Always on (no email involved): `queue.jsonl`, and draining `channel/in` in `_handle_inbox` (after email, and
     never while KILL is set). An answer of `STOP` from the drop folder creates KILL.
3. **`core/status_page.py` (new)**: `render(state, limits, now)` returns the HTML page (queue with Approve / Answer
   forms, current work, token and mail caps, capabilities, KILL/PAUSED banner; everything HTML-escaped).
   `serve(state, channel, port=8765)` binds `127.0.0.1` only and refuses any other host. Requests whose `Host` is not
   `127.0.0.1:<port>` or `localhost:<port>` are refused (DNS rebinding), and POSTs from another `Origin` are refused.
   `POST /stop` writes `state/KILL`; `POST /answer` drops an answer for the conductor. Run: `python -m core.status_page`.
4. **Drills** (1E gate): STOP by email halts; a reply answers the right question only; a foreign sender is ignored;
   the status-page Stop halts; the digest policy can't exceed one digest a day.

## Tests (tests/core/, all mail faked)

- `tests/core/test_channel.py`: pure functions (quiet hours, routing, queue view, digest text, drop folder).
- `tests/core/test_channel_conductor.py`: conductor wiring (held kinds, quiet hours, digest once a day, stalled
  digest, drop-folder answers and STOP, KILL silences everything, budget still applies, policy off = old behaviour).
- `tests/core/test_status_page.py`: render content and escaping; server on an ephemeral port: host check, origin
  check, stop, answer drop, refusal to bind a non-loopback address.

## Not in 1E

- The Dot round-trip trial (needs external setup). The drop folder and `queue.jsonl` are its interface point.
- Starting the status page at logon (the always-on service, 1D).
- Automatically applying a question's default at a deadline.
