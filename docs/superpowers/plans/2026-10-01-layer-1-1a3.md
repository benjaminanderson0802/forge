# Layer 1, sub-plan 1A (part 3): readiness check and capability map (4.1) and the 1A gate (7.5)

> Implements `docs/specs/layer-1-design.md` §4 (first bullet) and the 1A gate row of §7. Planned under
> `docs/specs/bootstrap-conductor.md` R41, R45, R60, R62 and R63. Requirements 1.1 to 1.6 belong to other 1A
> sub-plans and are not claimed here.

## What already exists

- `core/readiness.py`: the plain checks (`CHECKS`, `PLAIN_CHECKS`, `AI_NAMES`), `evaluate` (every check in its own
  daemon thread against one deadline; an exception or a late result is a failure), `write_map` (atomic), `read_map`,
  `broken`, `max_age_for`, `requirements`, `probe_ok`, `probe_agents`, and `diagnose` (condition plus one exact fix
  line per capability).
- `core/bootstrap.py`: `Conductor._refresh_readiness` (plain checks plus guarded, metered, cap-aware AI probes through
  `_guarded_run`; writes `<state>/capabilities.json`), `session_start` (readiness before every session),
  `step` (readiness first in every cycle, before any launch), `_route_capabilities` / `_cap_job` /
  `_file_cap_item` / `_capability_mail_check` (a failing check gets a Troubleshooter job or an item in Ben's queue
  with the exact fix), `ready_for` / `_stage_unready` / `_launch_gate` (no Builder starts while a capability it
  needs is broken). The design's `ledger/` is the conductor's state dir (`state/bootstrap`, or `state/lanes/<lane>`;
  see `2026-09-30-layer-1b2-readiness.md`), so `ledger/capabilities.json` is `<state>/capabilities.json`.
- Nothing checks the capability map against independent observation on the PC (gate 7.5).

So 4.1 gets an evidence task (R63) that proves it through the real conductor path with fake checks and fake
agents, and the gate gets an ordinary task that builds a readiness audit. The audit's real AI probes go through a
real `Conductor` running as its own unregistered lane of the live Forge root (R60), so they pass the stop check,
the atomic cap and runs-per-day admission, the launch's tamper guard and the shared two-provider meter exactly like
any other launch; it never launches an agent itself.

## L1A3_1: Readiness before every session and cycle, the capability map, routing and the builder gate

Covers 4.1. Evidence task (R63). Files in scope: `core/readiness.py`, `core/bootstrap.py`. Test file:
`tests/core/test_l1a_readiness_map.py`.

The code exists (see above). Change nothing unless a test or judge fails. The tests must pass on today's code and
fail on an empty `core/readiness.py` or `core/bootstrap.py`.

Fixture: subclass `tests.core.test_bootstrap.Harness` (temp git repo, `work`, `state`, `init(*tasks, agents=,
limits=, checks=, probes=)`, `task(**kw)`, `write_tests`, `build_feature`, `self.mails`). Patch
`core.agents.launch` with `side_effect=AssertionError` so no real process can start. Checks are counting fakes for
the eight plain names of `HEALTHY_CHECKS`, each appending `('check', name)` to a shared `events` list and returning
a per-name result (default `(True, '<name> fine')`). Probes are `FakeAgent`s for `claude` and `codex` (provider set)
replying `('ok', 5)` by default. Team agents are `FakeAgent`s whose scripts append `('agent', role)` to `events`.
The conductor clock is a controlled value `now` (start `2026-09-30T08:00:00+00:00`), also set on `c.meter.clock`.
Limits: `{'claude_daily_token_cap': 10**9, 'codex_daily_token_cap': 10**9}` plus what a criterion names.

Acceptance criteria:
1. Before every cycle. Two `c.step()` calls at the same clock: every plain check except `gmail` and `browser` is
   called exactly once per step (their 30-minute ok cache, `core.readiness.ok_ttl_s`, applies), and after advancing
   the clock 1801 s a third step calls `gmail` and `browser` again. In each step every `('check', ...)` event comes
   before the first `('agent', ...)` event of that step (`_refresh_readiness` runs before any launch).
2. Before every session. `c.session_start()` on a clean start calls every plain check once and both probes once,
   and returns the map now on disk. With `state/KILL` present, or `state/PAUSED`, or with
   `claude_daily_token_cap` 0, `session_start()` returns `{}` and calls no check and no probe.
3. The map. After `c.step()`, `state/capabilities.json` (the conductor's ledger dir) is a JSON object with exactly
   the ten names (eight plain plus `claude`, `codex`); every entry has exactly the keys `ok` (bool), `detail` (str,
   at most `core.readiness.DETAIL_MAX` characters) and `checked_at` (an ISO timestamp equal to the conductor clock,
   timezone-aware). A check that raises `RuntimeError('boom')` is stored as `ok` False with detail
   `RuntimeError: boom`; a check returning a 1000-character detail is cut to `DETAIL_MAX`; a probe replying
   `('nope', 3)` is stored as `ok` False with a detail containing `nope`; a probe replying `('ok', 5)` is stored as
   `ok` True with detail `ok (5 tokens)` and its run folder `state/runs/*-probe-claude-*` holds `prompt.md` equal to
   `core.readiness.PROBE_PROMPT`, and `c.meter.used_today('claude')` rose by 5. No `*.tmp` file is left in `state`.
   `core.readiness.read_map` of the file equals the dict `_refresh_readiness` returned.
4. A failing check starts a Troubleshooter job. A task with `needs=['docker']` brought to `tests_ok` (one step with
   `write_tests`), then `docker` returns `(False, 'error during connect: cannot connect to the Docker daemon')`:
   the next `c.step()` launches the troubleshooter exactly once with a prompt starting
   `You are the TROUBLESHOOTER. CAPABILITY FIX JOB: docker` that contains the detail, the condition `daemon_down` and
   the fix line containing `Docker Desktop.exe`; the builder is not launched in that step; the docker check runs once
   more after the job (the forced re-check). When the job's script makes `docker` healthy, the map shows docker
   `ok` True after that step, no capability item stays open, and the next step launches the builder.
5. Or an item in Ben's queue with the exact fix. With `git` returning `(False, 'git not installed or not on PATH')`:
   `c.step()` returns `not_ready`, no team agent is launched, `state/questions.json` has exactly one open item with
   `kind` `capability`, `capability` `git`, `condition` `missing`, `delivered` True, and one email whose body
   contains `Paste this into PowerShell:\nwinget install --id Git.Git -e`. A second step adds no item and no email.
   With `limits['cap_trouble_max'] = 0` and `docker` failing as in criterion 4, the docker item is filed (no
   Troubleshooter job is launched) with a fix line containing `Docker Desktop.exe`.
6. No Builder starts while a capability its contract needs is broken. With `cap_trouble_max` 0, a task with
   `needs=['docker']` at `tests_ok` and `docker` failing: three steps launch no builder, the task's `waiting_on` is
   `['docker']`, and `c.ready_for('builder', task)` names `docker` with a reason starting `failing:`. A direct
   `c._call('builder', 'x', None, needs=['docker'])` raises `core.bootstrap.NotReady` whose `names` has `docker`, and
   no new folder appears in `state/runs`. A second task in the same queue without `needs` still runs (its test
   writer is launched). A builder whose provider probe fails (`claude` probe replying `('nope', 3)`) is not launched
   either, and `ready_for('builder', task)` names `claude`. A need with no check (`needs=['vpn']`) makes
   `ready_for` report `vpn` as `no evidence`. After `docker` turns healthy, the next step launches the builder.

## L1A3_2: 1A gate: adapter tests plus a truthful readiness audit on the PC

Covers 7.5. Ordinary task. Depends on L1A3_1. Files in scope: `core/readiness_audit.py` (new). Test file:
`tests/core/test_l1a_gate.py`. Needs: claude, codex, github, gmail, docker, n8n, ollama, python_libs, browser.

Gate 7.5 is: the adapter tests pass, and the readiness check shows every capability truthfully on the PC. Build
`core/readiness_audit.py` (standard library plus what `core` already uses). It never launches an AI agent itself:
the real AI probes run inside a real `core.bootstrap.Conductor` that is its own lane, `AUDIT_LANE =
'readiness_audit'`, of the live Forge root (R60). So every probe passes the conductor's stop check, the atomic
admission against the shared caps, holds and runs per day (`_admit`), the tamper guard, and is metered in the shared
two-provider meter (`state/shared/meter/readiness_audit.json`), exactly like any launch. The probe agents are
`core.bootstrap.real_probes(limits)` (`ClaudeAgent` in plan mode and the isolated `CodexAgent`, read-only). The lane
is never registered in `state/lanes.json`, so the watchdog never starts it.

- `PLAIN = tuple(core.readiness.PLAIN_CHECKS)`, `AI = tuple(core.readiness.AI_NAMES)`, `ALL = PLAIN + AI` (the ten
  names of `core.readiness.CHECKS`).
- `OBSERVERS: dict[str, Callable[[float], tuple[bool, str]]]`, one per plain name, each taking a timeout in seconds
  and observing the same service by a different mechanism from `core.readiness`. Every subprocess runs through
  `core.agents.launch(args, cwd=Path.home(), stdin_text, timeout)` (hidden, below normal priority, whole tree killed
  on timeout); an executable not found by `shutil.which` gives `(False, '<name> not installed or not on PATH')`; any
  exception gives `(False, '<Type>: <msg>')`; details are at most 300 characters.
  - git: `git hash-object --stdin` with stdin `forge\n`; ok when stdout equals
    `hashlib.sha1(b'blob 6\x00forge\n').hexdigest()`.
  - github: `gh api user --jq .login` exits 0 with a non-empty login.
  - docker: `docker version --format {{.Server.Version}}` exits 0 with a non-empty version.
  - n8n: `http.client.HTTPConnection('127.0.0.1', 5678)` GET `/healthz`, ok on a 2xx status.
  - ollama: GET `http://127.0.0.1:11434/api/version` with `http.client`, ok when the JSON has a string `version`.
  - python_libs: a separate `sys.executable -c` process that really imports (`importlib.import_module`) requests,
    yaml, httpx, pandas, pdfplumber, keyring and playwright and prints a JSON list of the ones that failed; ok when
    it exits 0 and the list is empty, else the detail names them.
  - gmail: the `forge-gmail` keyring password for `core.readiness.GMAIL`; `smtplib.SMTP('smtp.gmail.com', 587)`,
    `starttls()`, `login`, `quit` (nothing is sent, no mailbox is read). The password never appears in any detail
    (any occurrence is replaced by `***`).
  - browser: a separate `sys.executable -c` process that launches headless Chromium with Playwright, sets content
    `<p>forge</p>`, prints the paragraph's text and closes; ok when the output is `forge`.
- `observe(observers, timeout_s) -> dict[str, dict]`: runs them concurrently in daemon threads against one deadline
  and returns `{name: {'ok': bool, 'detail': str}}`; one that has not reported by the deadline is
  `{'ok': False, 'detail': 'observer timed out'}`.
- `audit_conductor(root: Path, work_root: Path, limits: dict, checks=None, probes=None) -> Conductor`:
  `Conductor(repo=root, work=core.lanes.work_dir(work_root, AUDIT_LANE), state=core.lanes.state_dir(root / 'state',
  AUDIT_LANE), team=core.bootstrap.real_team(limits), limits=limits, owner_email=core.readiness.GMAIL, mailer=<records,
  sends nothing>, inbox=lambda: [], gh=lambda a: (0, ''), push=False, checks=core.bootstrap.real_checks() if checks
  is None else checks, probes=core.bootstrap.real_probes(limits) if probes is None else probes,
  shared=core.lanes.shared_dir(root / 'state'), lane=AUDIT_LANE)`. Constructing it launches nothing.
- `trace_ai(c, name, entry, meter_before: int, started: datetime) -> dict` (`{'truthful', 'why', 'run',
  'output_sha256'}`) for `claude` and `codex`, using the conductor's own captured run record and the audit's own
  judging rule (it does not call `core.readiness.probe_ok`):
  - the entry must be a dict with bool `ok`, str `detail` and a timezone-aware `checked_at` no older than
    `core.readiness.max_age_for(name, c.limits)` seconds at the audit's time (else `stale evidence` or `malformed`);
  - the run is the earliest folder `c.state / 'runs' / '<YYYYMMDDTHHMMSS>-probe-<name>-<hex>'` whose UTC timestamp is
    at or after `checked_at` truncated to the second and at most 3600 s after it (else `no probe run`);
  - its `prompt.md` must equal `core.readiness.PROBE_PROMPT` (else `prompt differs`) and its `output.json` must have
    `provider == name` (else `provider differs`);
  - observed ok is `output['ok'] is True and str(output['text']).strip().lower().startswith('ok')`; it must equal the
    entry's `ok` (else `ok differs`);
  - an ok entry needs recorded `tokens > 0` and detail exactly `ok (<tokens> tokens)`; a failing entry needs detail
    equal to the first 300 characters of the recorded `error`, or of `unexpected reply: <text[:100]>` when the error
    is empty (else `detail differs`);
  - when the run's timestamp is at or after `started` (it ran during this audit), `c.meter.used_today(name) -
    meter_before` must be at least its recorded tokens (else `not metered`).
  `run` is the run folder's name and `output_sha256` the sha256 of its `output.json`.
- `audit(root: Path, out_dir: Path, *, limits=None, checks=None, probes=None, observers=None, timeout_s=None,
  clock=None) -> dict`: limits default `core.agents.load_limits(root)`; `timeout_s` default
  `max(5, check_timeout_s - 15)`; observers default `OBSERVERS`; clock default UTC now. Steps:
  1. `c = audit_conductor(root, out_dir, limits, checks, probes)`. If `c._kill_set()`, nothing is checked or
     launched and the report has `stopped: True` and `truthful: False`.
  2. `meter_before = {p: c.meter.used_today(p) for p in AI}`; `started = clock()`.
  3. `m = c._refresh_readiness(force=set(PLAIN) & set(c.checks))`: every plain check runs now; the AI probes follow
     the conductor's own rules (ok reused inside `ai_check_ttl_h`, a failure not retried inside
     `readiness_fail_retry_s`, a capped or held provider never probed). `Capped`, `Stopped`, `Tampered`, `NotReady`,
     `RuntimeError` and `OSError` are caught and reported as `error` with `truthful: False`.
  4. `persisted = core.readiness.read_map(c.state / 'capabilities.json')`; it must equal `m` (else `map differs`
     and `truthful: False`); `map_sha256` is the sha256 of that file.
  5. `observed = observe(observers, timeout_s)`. A plain name is truthful when its persisted entry exists, has bool
     `ok`, str `detail` and a timezone-aware `checked_at` not before `started` minus 1 s and within 600 s after it,
     and its `ok` equals the observed `ok` (a failure both see is truthful; a disagreement or an observer timeout is
     not).
  6. Each AI name is traced with `trace_ai`; an AI name absent from the map is untruthful with `not probed`.
  7. Report: `{'checked_at', 'root', 'lane', 'state_dir', 'map_sha256', 'map', 'plain': {name: {'map', 'observed',
     'truthful', 'why'}}, 'ai': {name: {'map', 'run', 'output_sha256', 'truthful', 'why'}}, 'missing': [names of ALL
     absent from the map], 'meter': {'before', 'after'}, 'stopped', 'error', 'truthful'}`; `truthful` is True only
     when not stopped, no error, nothing missing and every entry is truthful. It is written atomically (temp file
     plus `os.replace`, LF, sorted keys) to `out_dir / 'readiness_audit.json'` and to
     `c.state / 'readiness_audit.json'`, and returned.
- `main(argv=None) -> int`: `python -m core.readiness_audit [--root PATH] [--out DIR]`; root default env
  `FORGE_LIVE_ROOT` else `Path.home() / 'Forge'`; out default a new temp folder. It calls `audit(root, out)` with no
  fakes (the real checks, real probes and `OBSERVERS`), prints one line per capability (`OK`/`FAIL`, truthful or
  not, the detail, the why) and the report path, and returns 0 when truthful, else 1.

Fake-root fixture (criteria 2 to 6): a temp `root` with `charter/limits.json` = the repo's limits with
`check_timeout_s` 20, and an empty `state/`. Checks are counting fakes for the eight plain names; probes are
`FakeAgent`s with providers `claude` and `codex`; observers are fakes taking a timeout.

Acceptance criteria:
1. Adapter tests. A subprocess `[sys.executable, '-m', 'unittest', 'tests.core.test_agents', 'tests.core.test_usage',
   'tests.core.test_usage_holds', 'tests.core.test_l1a_readiness_map']` run from the repo root (timeout 900 s) exits
   0 and its output reports `OK`.
2. Agreement logic. Fake checks and observers that agree (including `docker` failing in both) and probes replying
   `('ok', 5)` give `truthful` True, with docker's `map.ok` False; a check saying ok while its observer says not ok
   makes that name and the report untruthful with a non-empty `why`; an observer that sleeps 30 s with
   `timeout_s=1` makes `audit` return within 10 s with `observer timed out` and `truthful` False. A probe replying
   `('nope', 3)` is a truthful failure (its entry is `ok` False and traced to its run).
3. The conductor's controls hold. After an audit with the fake probes: each probe ran exactly once, through a run
   folder under `root/state/lanes/readiness_audit/runs/` named `*-probe-<name>-*`; `c.meter.used_today('claude')`
   rose by 5 and `root/state/shared/meter/readiness_audit.json` exists; `core.lanes.listed(root / 'state') ==
   ['main']` (never registered). With `limits['claude_daily_token_cap'] = 0` the claude probe is never called, the
   report's `ai.claude.why` is `not probed` and `truthful` is False. With `root/state/shared/KILL` present no check,
   probe or observer is called and the report has `stopped` True and `truthful` False. A second audit within
   `ai_check_ttl_h` calls neither probe again (the conductor's cache) and still traces both to the first runs.
4. `trace_ai` negatives, on a real run folder made by criterion 3: an entry whose `ok` differs from the record, a
   detail with a different token count, a `prompt.md` rewritten, an `output.json` with another provider, an entry
   whose `checked_at` is after every run, and an entry older than `max_age_for` each give `truthful` False with the
   named reason.
5. The report. `out_dir/readiness_audit.json` and `root/state/lanes/readiness_audit/readiness_audit.json` both
   parse to the returned report; it covers all ten names; `map_sha256` is the sha256 of the persisted
   `capabilities.json`; each AI entry's `output_sha256` is the sha256 of the traced `output.json`.
6. No fakes in the real path. `audit_conductor(root, tmp, limits)` without checks or probes has
   `set(c.checks) == set(PLAIN)`, `c.probes['claude']` a `core.agents.ClaudeAgent` with `permission_mode == 'plan'`
   and `c.probes['codex']` a `core.agents.CodexAgent` with `sandbox == 'read-only'` (constructing launches
   nothing). With `core.readiness_audit.audit` patched by a recorder, `main(['--root', str(root), '--out',
   str(out)])` calls it once with exactly those two arguments and no checks, probes or observers.
7. Truthful on the PC (the live gate check). When the live root (env `FORGE_LIVE_ROOT`, else `Path.home() /
   'Forge'`) has `charter/limits.json` and `state/shared/migrated.json`, one `audit(root, tmp)` with no fakes (real
   `CHECKS` through the audit lane, real probes admitted and metered by that conductor, real `OBSERVERS`) runs once
   for the test class and: finishes within `4 * check_timeout_s + 120` seconds; writes `tmp/readiness_audit.json`
   equal to the returned report; the persisted map has all ten names; every plain entry's `checked_at` is at or
   after the audit start (checked now, not cached); every AI entry is traced to a run folder that exists under the
   lane's `runs/` with a matching `output_sha256`; the live `state/lanes.json` is unchanged; and the report has
   `truthful` True. A capability that is really down is fine when the map says so and the observer agrees; on
   failure the test message lists every untruthful entry with its `why`. When that live root does not exist (CI,
   Linux) only this test is skipped, with that reason.

## Self-check against the rules (R45)

- R1 / R4 / R63: every `test_cmd` is `python -m unittest <its own test file>`; L1A3_1 is an evidence task whose
  tests pass on today's code and fail on an empty in-scope module; L1A3_2 builds a module that does not exist, so its
  tests fail on the current code.
- R14 / R15 / R60: the audit's only writes under the live root are those of its own lane conductor (its own
  `state/lanes/readiness_audit/` and its own registered meter file), which is how R60 lanes are meant to share caps;
  main's `state/bootstrap` and other lanes are never written. The lane is never registered.
- D-020 / R37 / R51 / R60a: AI is launched only inside `Conductor._guarded_run`, admitted against the shared daily
  caps, holds and runs per day, and metered in the shared meter. A capped provider is never probed; the gate then
  reports it as not probed instead of launching.
- Design 1.4: the Codex probe is the real `CodexAgent` (isolated flags; proven by `tests.core.test_agents`, which the
  gate runs).
- D-030 / D-035: the gate runs against the real services on Ben's PC; truthful failures are reported as failures,
  and the gate fails when any map entry disagrees with what was independently observed or traced.
- Don't interfere with Ben: every observer subprocess is hidden and below normal priority; the browser is headless.

## Reviewer notes

- L1A3_2: Serialize audits sharing the fixed readiness_audit lane using its conductor lock. Concurrent gate, CLI, or judge runs must not write the same lane state during another audit's tamper checks.
- L1A3_2: Run-folder timestamps have second precision, while started includes microseconds. Account for this when identifying newly launched probes so same-second runs cannot bypass the metering assertion. Test this boundary.
- L1A3_2: Keep the injected audit clock, conductor clock, and meter clock consistent. Reject future-dated AI evidence and return an untruthful report for missing or malformed run artifacts rather than raising unexpectedly.
